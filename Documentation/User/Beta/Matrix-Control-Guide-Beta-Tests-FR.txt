BIENVENUE
--------------------------------------------------------------------------------

Merci de participer aux bêta-tests du Matrix-Control ! :)

Le Matrix-Control est un éditeur MIDI moderne pour les synthétiseurs Oberheim
Matrix-1000, Matrix-6 et Matrix-6R. Utilisable en application autonome ou en
plugin, il sert de « télécommande » à l'écran : il envoie et reçoit des
messages MIDI (réglages, patches, master) pour que vous puissiez voir et modifier le synthé plus confortablement. En revanche, il ne produit pas le son et ne l'enregistre pas non plus — le flux audio sort toujours du synthétiseur.
Pour l'entendre, vous devrez brancher la sortie audio du synthé sur une entrée de votre interface audio, votre table de mixage ou vos enceintes.

--------------------------------------------------------------------------------
À QUOI SERT CE GUIDE ?
--------------------------------------------------------------------------------

Ce document n'est pas un cours sur la synthèse sonore, ni le manuel utilisateur
complet du Matrix-Control. C'est un guide de TESTS : une liste de situations
concrètes à rejouer chez vous, pour vérifier que tout se comporte correctement
sur la version bêta du logiciel, avant la diffusion d'une version finale et
stable par le développeur. Vos retours (surtout les bugs et les moments de
confusion) sont précieux !

Comment utiliser ce guide de tests ?
------------------------------------
Parcourez-le dans l'ordre, du début à la fin. Chaque section correspond à une
étape naturelle : installer, brancher le synthé, démarrer, éditer, etc.

1. Ouvrez-le dans n'importe quel éditeur de texte basique (TextEdit sous macOS,
   Bloc-notes sous Windows, gedit sous Linux, etc.), ou imprimez-le.
3. Au fur et à mesure, remplacez les [ ] par [x] devant les étapes que vous avez
   effectuées, ou cochez-les à la main si vous imprimez ce document.
4. Quand une étape ne concerne pas votre installation (par exemple le format de
   plugin AudioUnit « AU » si vous êtes sous Windows, ou BANK UTILITY si vous
   testez sur un Matrix-6/6R et non un Matrix-1000), écrivez simplement
   « sans objet » à côté, ou ignorez-la.
5. Notez vos observations dans la zone « Notes » de la section où le problème
   apparaît — pas besoin de revenir en arrière plus tard.
6. Vous n'irez peut-être pas jusqu'au bout de ces tests : c'est normal. Les
   premières sections (installation, démarrage, MIDI, édition de base) sont les plus importantes. Si vous vous arrêtez après le parcours rapide, vos retours restent très utiles au développeur !
7. Si quelque chose échoue, notez ce que vous voyez : le message exact à
   l'écran aide beaucoup, n'hésitez pas à le recopier si vous le pouvez.

Deux rythmes possibles
----------------------
- Le parcours RAPIDE (section 20) : environ 30 à 45 minutes, pour voir si
  l'essentiel du logiciel fonctionne sur votre ordinateur.
- Le parcours COMPLET (section 21) : une session de tests plus longue, quand
  vous avez le temps d'explorer davantage.

Une seule combinaison ordinateur + logiciel de MAO (DAW) + synthé Oberheim + Matrix-Control suffit déjà à être utile. Si vous pouvez tester sur plusieurs modèles de synthés, tant mieux — mais ce n'est pas obligatoire.

À propos des noms affichés à l'écran
------------------------------------
L'interface graphique (GUI) du Matrix-Control est uniquement en anglais. Dans ce
guide, les noms des écrans et boutons restent donc en anglais, comme vous les
voyez : GETTING STARTED, PATCH EDIT, BANK UTILITY, etc. Le reste du texte est
en français dans ce guide, pour mieux vous accompagner.

Repère rapide dans la fenêtre principale
----------------------------------------
Une fois le logiciel ouvert, la zone centrale s'organise à peu près ainsi :

  +----------------------------------------------------------------------+
  |  Logo MATRIX-CONTROL    |   Ports MIDI (FROM SYNTH, TO SYNTH, etc.)  |
  +----------------------------------------------------------------------+
  |                         |                          |                 |
  |  PATCH EDIT             |  MATRIX MODULATION       |  MASTER EDIT    |
  |  - 10 modules de son :  |  (10 bus de modulation)  |  (Matrix-1000   |
  |    DCO, VCF, ENV, etc.  |                          |   seulement ;   |
  |  - 5 afficheurs :       |--------------------------|   grisée sur    |
  |    - 3 Enveloppes       |  PATCH MANAGER           |   Matrix-6/6R)  |
  |    - 1 Track Generator  |  - INTERNAL PATCHES      |                 |
  |    - 1 Patch Name       |  - COMPUTER PATCHES      |                 |
  |                         |  - BANK UTILITY          |                 |
  |                         |  - PATCH MUTATOR         |                 |
  +----------------------------------------------------------------------+
  |  Messages en bas de fenêtre               Badge DEVICE (type synthé) |
  +----------------------------------------------------------------------+

Vocabulaire utile (aligné sur le manuel utilisateur) :
- Fenêtre = la fenêtre principale du Matrix-Control, ou une fenêtre qui
  s'ouvre par-dessus (Settings, About)
- Panneau = grandes régions de la fenêtre principale (HEADER, BODY, FOOTER)
  — Settings n'est pas un panneau
- Section = grand bloc à l'intérieur du panneau BODY (PATCH EDIT, MATRIX
  MODULATION, PATCH MANAGER, MASTER EDIT)
- Module = bloc à l'intérieur d'une section (DCO 1, INTERNAL PATCHES,
  PATCH MUTATOR, MIDI, VIBRATO, MISC, BANK UTILITY, etc.)
- Groupe = sous-partie d'un module (BROWSER, MEMORY, STORAGE, etc.)
- Bus de modulation = une des dix lignes de MATRIX MODULATION
- Dialogue = petite boîte de confirmation ou de choix (Unsaved patch,
  RESET MASTER, alertes du Mutator, etc.)

Un manuel utilisateur plus détaillé peut être fourni avec le Matrix-Control ;
ce guide de tests ne le remplace pas.

2. POINTS IMPORTANTS AVANT DE COMMENCER
--------------------------------------------------------------------------------

Ces points évitent de prendre pour des bugs des comportements voulus, ou
des messages habituels sous macOS / Windows.

2.1. Distribution en fichier ZIP
----------------------------------
Le Matrix-Control arrive dans une archive ZIP, sans assistant d'installation.
Vous extrayez l'archive, puis vous copiez vous-même l'application et/ou les
plugins aux endroits habituels de votre système (détail en section 4). Ce
n'est pas un oubli : pour cette version bêta, il n'y a pas encore d'assistant
d'installation classique du type « Lancer > Suivant > Suivant > ... > Terminer ».

2.2. Messages de sécurité de macOS ou Windows
-----------------------------------------------
Les fichiers exécutables de la bêta ne passent pas encore par la certification payante d'Apple (« notarisation ») ni par la signature éditeur Microsoft Windows.

Résultat fréquent et NORMAL :

- sous macOS : avertissement du type « développeur non identifié » ;
- sous Windows : écran SmartScreen du type « Windows a protégé votre PC ».

Ce n'est en général PAS un virus ni un bug du plugin. La section 4 explique
comment continuer en confiance (par exemple clic droit → Ouvrir sous macOS).

2.3. Écoute audio Standalone sous Windows (ASIO)
--------------------------------------------------
En mode Standalone (l'appli seule, hors DAW), le Matrix-Control peut écouter
le retour audio de votre synthé via l'interface audio connectée à votre
ordinateur. Sous Windows, cela passe souvent par le pilote audio du système
(parfois appelé WASAPI).

À terme, le Matrix-Control devrait aussi proposer l'ASIO : un pilote très
utilisé en MAO, en général plus réactif (latence plus faible). Pour l'instant,
ASIO peut encore être absent des premières versions bêta : le développeur
attend un accord de licence avec Steinberg, l'éditeur et propriétaire de
cette technologie. Si vous ne voyez pas ASIO dans la liste audio, ce n'est
donc pas un bug : notez-le, et vérifiez surtout que l'écoute marche avec le
pilote système. L'essentiel reste d'entendre le synthé et de pouvoir l'éditer.

2.4. Protégez vos patches avant de démarrer les tests
-------------------------------------------------------
Certaines étapes des tests demandent d'enregistrer un patch dans la mémoire
du synthé (STORE) ou de générer des variations (PATCH MUTATOR). Si vous tenez
à des patches déjà présents en mémoire dans votre Matrix-1000/6/6R,
sauvegardez-les d'abord sur votre ordinateur une fois le logiciel installé
(section 4) : module COMPUTER PATCHES, bouton SAVE AS, fichiers au format
.syx — avant de faire des essais d'écriture dans le synthé.

2.5. Si STORE semble ne pas enregistrer (Matrix-1000)
-------------------------------------------------------
Sur un Matrix-1000, une protection mémoire ou un verrouillage de banque
(MEMORY PROTECT / BANK LOCK, sur la machine ou dans MASTER EDIT) peut
empêcher l'écriture des patches. Vérifiez cela avant de conclure à un bug.

4. INSTALLER LE MATRIX-CONTROL
================================================================================

Le Matrix-Control est fourni sans assistant d'installation. Vous devez donc extraire l'archive ZIP, copier les fichiers exécutables aux endroits indiqués, puis éventuellement demander à votre DAW de rescanner la liste des plugins.

Le but ici : installer et vérifier que le logiciel s'ouvre. Branchez le synthé juste après (section 5), avant de remplir l'assistant GETTING STARTED (section 6). Si cet assistant s'ouvre trop tôt pendant l'installation, choisissez CONFIGURE LATER et continuez — vous le reprendrez une fois le MIDI en place.

--------------------------------------------------------------------------------
4.1. Contenu de l'archive ZIP
--------------------------------------------------------------------------------
Selon votre système, vous devriez trouver au moins :

[ ] L'application autonome (Standalone)
[ ] Le plugin VST3
[ ] Sur macOS seulement : le plugin AU (sans objet sous Windows / Linux)
[ ] De la documentation (manuel utilisateur et/ou ce guide de tests)

Si quelque chose manque, notez le nom exact du fichier ZIP et ce qui est absent.

--------------------------------------------------------------------------------
4.2. Tester sous macOS
--------------------------------------------------------------------------------

Cette section concerne macOS sur processeur Apple Silicon ou Intel.

Où copier les fichiers :

  Plugin AU   →  ~/Library/Audio/Plug-Ins/Components/
  Plugin VST3 →  ~/Library/Audio/Plug-Ins/VST3/
  Application →  /Applications/
                 (ou à côté du ZIP, si vous préférez)

Étapes :
[ ] Extraire le ZIP
[ ] Copier Matrix-Control.component dans Components
[ ] Copier Matrix-Control.vst3 dans VST3
[ ] (Optionnel) Copier Matrix-Control.app dans Applications
[ ] Après un téléchargement navigateur / GitHub, il faut lever le « drapeau
    de
    quarantaine » (sinon macOS peut afficher que l'app ou le plugin est
    « endommagé » / « damaged »). Méthode pas à pas :

    1. Ouvrir l'application « Terminal » de macOS :
       - Raccourci le plus simple : touche Commande (⌘) + barre d'espace
         pour ouvrir Spotlight, taper Terminal, puis Entrée.
       - Autre chemin : Finder → Applications → Utilitaires → Terminal.
    2. Dans la fenêtre Terminal, taper exactement ceci, puis un espace
       (ne validez pas encore) :

         xattr -cr

    3. Dans le Finder, glisser-déposer sur la fenêtre Terminal chacun des
       fichiers que vous avez copiés (Matrix-Control.app,
       Matrix-Control.vst3, Matrix-Control.component). macOS écrit le
       chemin complet tout seul après chaque glisser-déposer. Séparez
       les fichiers par un espace. Vous pouvez omettre un fichier que
       vous n'avez pas installé.
    4. Quand la ligne ressemble à ceci (vos chemins peuvent différer) :

         xattr -cr /Applications/Matrix-Control.app \
                   /Users/vous/Library/Audio/Plug-Ins/VST3/Matrix-Control.vst3 \
                   /Users/vous/Library/Audio/Plug-Ins/Components/Matrix-Control.component

       appuyez sur Entrée. En général, Terminal n'affiche rien de plus
       si la commande a réussi — c'est normal.
    5. Quitter Terminal : menu Terminal → Quitter Terminal, ou ⌘Q.
       Vous n'en aurez plus besoin pour la suite de ce guide.

    Variante sans glisser-déposer : copier la commande d'exemple ci-dessus
    (sélection à la souris, puis ⌘C), coller dans Terminal (⌘V), remplacer
    les chemins par les vôtres, puis Entrée. Sur succès, passer à l'étape 5.

[ ] Premier lancement : si macOS dit « développeur non identifié »,
    clic droit → Ouvrir, ou autoriser dans Réglages Système.
    C'est attendu pour cette bêta. Ce n'est pas un bug.
[ ] Lancer le Standalone : la fenêtre s'ouvre
    (si GETTING STARTED apparaît : CONFIGURE LATER pour l'instant — section 6)
[ ] Dans le DAW : rescanner si besoin ; le Matrix-Control apparaît en AU
    et/ou VST3
[ ] Charger le plugin sur une piste instrument / MIDI

Ce qui est normal :
- l'appli et les plugins démarrent ;
- après xattr, plus de message « endommagé » / « damaged » en principe ;
- un avertissement « développeur non identifié » peut encore apparaître :
  clic droit → Ouvrir.

4.3. Tester sous Windows
--------------------------------------------------------------------------------

Cette section concerne Windows 10 ou Windows 11.

Où copier les fichiers :

  Plugin VST3 →  C:\Program Files\Common Files\VST3\
                 (souvent réservé aux administrateurs)
  Standalone  →  Matrix-Control.exe (où vous voulez)

Étapes :
[ ] Extraire le ZIP
[ ] Copier Matrix-Control.vst3 vers le dossier VST3 indiqué plus haut
    (C:\Program Files\Common Files\VST3\).

    Si Windows refuse la copie (message du type « vous devez être
    administrateur » ou « accès refusé »), ce n'est pas bloquant.
    Choisissez l'une de ces alternatives :

    A. Dossier VST3 de votre compte utilisateur — créez par exemple :

         C:\Users\VotreNom\Documents\VST3\

       (remplacez VotreNom par le nom de votre session Windows), puis
       copiez Matrix-Control.vst3 dedans.

    B. Un dossier « plugins » déjà utilisé par votre DAW — certains
       logiciels (Ableton Live, Reaper, Cubase, etc.) ont leur propre
       dossier de plugins, ou permettent d'en ajouter un dans leurs
       préférences.

    Ensuite, dites au DAW où chercher : ouvrez les préférences /
    options du DAW, section Plugins / VST / VST3, ajoutez le dossier
    choisi (A ou B) s'il n'y est pas déjà, puis lancez un rescan
    (souvent un bouton du type « Rescan », « Scan », ou « Actualiser »).
    Sans cette étape, le Matrix-Control peut être bien copié sur le
    disque mais invisible dans la liste des instruments.

[ ] Lancer Matrix-Control.exe (double-clic sur le fichier)
    (si GETTING STARTED apparaît : CONFIGURE LATER pour l'instant — section 6)
[ ] Si Windows affiche SmartScreen (« Windows a protégé votre PC ») :

    C'est attendu pour cette bêta : le fichier n'a pas encore la signature
    payante d'un éditeur Windows. Ce n'est en général PAS un virus.

    1. Sur l'écran bleu / sombre SmartScreen, cliquez
       « Informations complémentaires » (lien souvent en bas à gauche,
       facile à manquer).
    2. Un bouton « Exécuter quand même » apparaît : cliquez dessus.
    3. Si Windows demande une confirmation administrateur, acceptez.

    Si vous ne voyez que « Ne pas exécuter » sans le lien supplémentaire,
    agrandissez la fenêtre ou cherchez « Informations complémentaires »
    avant d'abandonner.

[ ] Dans le DAW : rescanner les VST3 ; charger le Matrix-Control
[ ] Sous Windows, un port MIDI est souvent réservé à une seule application.
    Si le Matrix-Control n'ouvre pas le port, fermez l'autre logiciel qui
    l'utilise, puis réessayez.

Ce qui est normal :
- Standalone et VST3 démarrent ;
- le plugin apparaît après un rescan dans le DAW ;
- SmartScreen peut réapparaître au premier lancement : même procédure.

4.4. Tester sous Linux
--------------------------------------------------------------------------------

Cette section concerne Linux, en pratique Ubuntu 24 / 26 ou une distribution proche.

Où copier les fichiers :

  Plugin VST3 →  ~/.vst3/
                 (dossier « .vst3 » dans votre dossier personnel ; le point
                 au début signifie qu'il est souvent masqué dans le

  Standalone  →  binaire nommé Matrix-Control (ou proche) fourni dans le ZIP
                 — placez-le où vous voulez (Bureau, Applications, etc.)

Étapes :
[ ] Extraire le ZIP (clic droit → Extraire ici, ou double-clic selon
    votre gestionnaire d'archives)
[ ] Créer le dossier du plugin s'il n'existe pas encore, puis y copier
    Matrix-Control.vst3.

    Méthode avec le gestionnaire de fichiers (Nautilus sous Ubuntu) :
    1. Ouvrez votre dossier personnel (Maison / Home).
    2. Affichez les fichiers cachés : Ctrl+H (ou menu Affichage →
       Afficher les fichiers cachés).
    3. Si le dossier « .vst3 » n'existe pas : clic droit → Nouveau dossier,
       nommez-le exactement .vst3 (avec le point).
    4. Copiez Matrix-Control.vst3 depuis le ZIP extrait vers ce dossier
       .vst3.

    Variante en ligne de commande (si vous préférez) : ouvrir Terminal
    (touche Super / Windows, taper Terminal, Entrée), puis :

      mkdir -p ~/.vst3
      cp /chemin/vers/Matrix-Control.vst3 ~/.vst3/

    Remplacez /chemin/vers/… en glissant le fichier .vst3 depuis le
    gestionnaire de fichiers vers la fenêtre Terminal après avoir tapé
    « cp » et un espace.

[ ] Rendre le Standalone exécutable si Linux refuse de le lancer
    (« Permission denied », icône grisée, ou rien ne se passe).

    1. Ouvrir Terminal (comme ci-dessus).
    2. Taper exactement ceci, puis un espace (ne validez pas encore) :

         chmod +x

    3. Glisser-déposer le fichier Matrix-Control (Standalone) depuis le
       gestionnaire de fichiers vers Terminal : le chemin s'écrit tout
       seul.
    4. Appuyer sur Entrée. En général, rien ne s'affiche si la commande
       a réussi — c'est normal.
    5. Quitter Terminal : menu → Quitter, ou Ctrl+D puis fermer la
       fenêtre, ou fermer simplement la fenêtre.

[ ] Lancer le Standalone :
    - double-clic sur le fichier dans le gestionnaire de fichiers, ou
    - depuis Terminal, pour voir d'éventuels messages d'erreur :

         /chemin/vers/Matrix-Control

      (même astuce : taper le début du chemin ou glisser le fichier,
      puis Entrée)
    Si GETTING STARTED apparaît : CONFIGURE LATER pour l'instant
    (vous le reprendrez en section 6, après le branchement).

[ ] Dans le DAW : rescanner la liste des plugins VST3 ; le Matrix-Control
    doit apparaître. Chargez-le sur une piste instrument / MIDI.
[ ] Ouvrir SETTINGS → AUDIO et noter ce qui est proposé (noms de
    périphériques, pilotes système type ALSA / PulseAudio / PipeWire,
    éventuellement JACK). Pas besoin de tout comprendre : l'idée est de
    savoir quel chemin audio Linux vous propose, pour le noter dans la
    fiche de session (section 3) si un problème audio apparaît plus tard.

Ce qui est normal :
- le Standalone et le VST3 démarrent ;
- aucun message bloquant du type « bibliothèque manquante »
  (shared library / .so introuvable) ;
- si un tel message apparaît quand même, copiez-le mot pour mot dans
  les notes — c'est utile pour le développeur.

================================================================================
5. CONNECTER LE SYNTHÉTISEUR
================================================================================

Avant d'ouvrir l'assistant GETTING STARTED, branchez le matériel. Sinon
l'étape MIDI de l'assistant n'aura rien à détecter — ou semblera « cassée »
alors que seuls les câbles manquent.

[ ] Synthé allumé
[ ] Interface MIDI allumée / reconnue par l'ordinateur
[ ] Câble MIDI de l'ordinateur vers le synthé
    (MIDI OUT de l'interface → MIDI IN du synthé)
[ ] Câble MIDI du synthé vers l'ordinateur
    (MIDI OUT du synthé → MIDI IN de l'interface)
    Les DEUX sens en même temps sont obligatoires.
[ ] Sortie audio du synthé branchée vers votre interface audio, table de
    mixage ou enceintes (pour entendre les changements pendant les tests)

Ne choisissez pas encore les ports MIDI dans le logiciel : ce sera l'étape
suivante (assistant GETTING STARTED), puis une vérification MIDI dédiée.

10. ÉDITER UN PATCH
================================================================================

Si quelque chose vous surprend pendant l'édition (Unison, mode clavier,
STORE, etc.), consultez aussi la section 19 (Points connus à vérifier) —
ce ne sont pas toujours des bugs.

Une fois le synthé détecté, chargez un patch via le module INTERNAL PATCHES
(dans la section PATCH MANAGER — détail section 12), puis travaillez dans
la section PATCH EDIT.

Chaque mouvement à l'écran est envoyé au synthé : vous devez entendre le
changement sur la machine.

Modules typiques dans PATCH EDIT :
  DCO 1 / DCO 2     oscillateurs
  VCF/VCA           filtre et volume
  FM/TRACK          FM + Track Generator
  RAMP/PORTAMENTO   rampes, portamento, mode clavier
  ENV 1 / 2 / 3     enveloppes
  LFO 1 / LFO 2     oscillateurs lents
  PATCH NAME        nom du patch (8 caractères)

--------------------------------------------------------------------------------
10.1. Gestes représentatifs
--------------------------------------------------------------------------------
[ ] Dans le module DCO 1, changez un paramètre (forme d'onde, désaccord…) :
    le son change
[ ] Dans VCF/VCA, bougez la fréquence de coupure ou la résonance : le son
    change
[ ] Sur une enveloppe (ENV), déplacez un point a la souris
[ ] Dans FM/TRACK, déplacez un point du Track Generator a la souris

--------------------------------------------------------------------------------
10.2. Boutons I / C / P sur un module
--------------------------------------------------------------------------------
Sur plusieurs modules, l'en-tête propose :
  I = Init   (remettre le module a des valeurs par défaut)
  C = Copy   (copier vers le presse-papiers)
  P = Paste  (coller depuis le presse-papiers)

[ ] I réinitialise le module
[ ] C puis P sur un module compatible fonctionne
[ ] Sur un module incompatible, P est grisé ; un clic peut afficher un
    message en bas de fenêtre

--------------------------------------------------------------------------------
10.3. Annuler / rétablir
--------------------------------------------------------------------------------
[ ] Annuler (Cmd+Z sous macOS, Ctrl+Z sous Windows/Linux) revient en arrière
[ ] Rétablir (Cmd+Shift+Z / Ctrl+Shift+Z) restaure
[ ] Charger un autre patch efface cet historique d'annulation

--------------------------------------------------------------------------------
10.4. Nom du patch
--------------------------------------------------------------------------------

Le nom s'affiche et s'édite dans le champ PATCH NAME (8 caractères).

[ ] L'afficheur PATCH NAME montre le nom actuel (8 caractères)
[ ] Double-clic pour renommer quand c'est autorisé :
    - Matrix-1000 : possible surtout sur les banques 0 et 1 (mémoire
      réinscriptible) ; souvent impossible sur les banques 2 a 9 (usine)
    - Matrix-6/6R : en général possible (pas de banques ROM du même type)
[ ] Sur une banque ou le renommage est refusé, le double-clic ne doit pas
    ouvrir d'édition (ou le champ reste bloqué) — notez ce que vous voyez
[ ] Le nom se met aussi a jour au chargement d'un patch ou après certaines
    actions du PATCH MUTATOR

Résultat attendu : édition audible, annulation cohérente, pas de fermeture
intempestive.

11. ÉDITER LA MATRICE DE MODULATION
================================================================================

C'est le « câblage » interne du synthé : on relie une source (LFO, enveloppe,
vélocité…) à une destination (filtre, hauteur…). Dix bus (lignes),
numéros 0 à 9.

Préparez : synthé détecté, un patch chargé.

[ ] Sur un bus : SOURCE, AMOUNT, DESTINATION (autre que NONE)
[ ] Jouez une note : la modulation s'entend / se sent
[ ] Le bouton I sur un bus remet ce bus à zéro
[ ] Si C / P existent au niveau de la section MATRIX MODULATION : copier /
    coller un bus (ou la section) se comporte de façon claire ; sinon
    notez « sans objet »
[ ] Réordonnez deux bus en glissant le numéro # : départ gris, arrivée rouge
    ;
    les contenus s'échangent, les numéros restent 0 a 9
[ ] Annuler après ce réordonnancement revient d'une étape

Résultat attendu : bus éditables, réordonnancement stable.

12. GÉRER LES PATCHES DANS LA MÉMOIRE DU SYNTHÉ

12.1. Navigation et STORE

[ ] Refaire : Discard — les modifications sont abandonnées, la navigation

[ ] Refaire : Store et/ou Save / Save As selon les boutons proposés — les

[ ] Après Discard / Store / Save : la suite de la navigation est cohérente

Résultat attendu : navigation fluide ; STORE / INIT / COPY / PASTE OK sur

14. CRÉER DES VARIATIONS DE PATCH
================================================================================

Le PATCH MUTATOR (dans PATCH MANAGER) crée des variations aléatoires
contrôlées du patch courant — pratique pour explorer des timbres.

Préparez : synthé détecté, patch chargé. Sauvegardez d'abord si le son de
départ vous est précieux.

Commutateurs de modules (choisir ce qui entre dans la mutation) :

  D1 = DCO 1
  D2 = DCO 2
  F/A = filtre / VCA (VCF/VCA)
  F/T = FM / Track Generator
  R/P = Ramp / Portamento
  E1 / E2 / E3 = enveloppes 1, 2, 3
  L1 / L2 = LFO 1 et 2
  MM = matrice de modulation (MATRIX MODULATION)

Réglages supplémentaires :

  AMOUNT — intensité de la variation
  RANDOM — degré d'aléatoire
  MODE — caractère de la mutation (ex. KINDRED, DRIFT, WARP, WILD)
  PITCH — traitement des hauteurs (ex. KEEP, CONSONANT, DISSONANT, FREE ; éventuellement une fenêtre d'octaves)

Boutons principaux :

  MUTATE — crée une nouvelle variation et l'envoie au synthé
  RETRY — autre tirage à partir du même point de départ
  HISTORY + `<` / `>` — parcourt les variations de la session
  C (Compare) — compare au départ et verrouille le reste de l'édition tant qu'il est actif
  D (Delete) — supprime l'entrée sélectionnée dans l'historique
  F (Flush) — vide l'historique de la session
  E (Export) — exporte la session en fichiers `.syx`

--------------------------------------------------------------------------------
14.1. Mutation de base
--------------------------------------------------------------------------------

[ ] Au moins un commutateur (D1, D2, F/A, …, MM) est activé
[ ] Réglez AMOUNT et RANDOM autrement que les défauts, puis MUTATE :
    variation audible / visible envoyée au synthé
[ ] RETRY propose une autre variante
[ ] HISTORY < / > parcourt la session
[ ] C (Compare) verrouille l'édition ; un message en bas de fenêtre le
    rappelle
[ ] Avec Compare actif : Undo/Redo patch et édition restent bloqués (rappel
    section 10.3)
[ ] Désactiver Compare restaure l'édition
[ ] D et F se comportent comme attendu (suppression / vidage) — avec
    prudence
[ ] E exporte la session ; rouvrir via COMPUTER PATCHES → OPEN
[ ] Dialogues (historique plein, mutations non exportées, dossier déjà
    existant) : choix clairs, pas de perte silencieuse

--------------------------------------------------------------------------------
14.2. MODE et PITCH
--------------------------------------------------------------------------------

[ ] Changer MODE (ex. KINDRED puis WILD) : MUTATE donne un caractère
    différent — décrivez ce que vous entendez
[ ] Changer PITCH (KEEP vs FREE / CONSONANT, etc.) : la hauteur des
    variations est cohérente avec le choix

Résultat attendu : mutations audibles, Compare qui bloque bien, MODE/PITCH
perceptibles, export rechargeable.

18. POINTS CONNUS À VÉRIFIER
================================================================================

Certains comportements surprennent. Confirmez ce que vous voyez.

[ ] Unison (surtout Matrix-1000) : dans le module RAMP/PORTAMENTO (et

    Un comportement bizarre côté firmware du synthé est connu ; il est

    Notez votre EPROM et ce qui se passe (notes collées, mode qui ne
    « prend » pas, etc.).
[ ] MEMORY PROTECT / BANK LOCK : s'ils sont actifs, STORE peut sembler
    cassé — vérifiez avant de signaler un bug.
[ ] Sur Matrix-6/6R : MASTER EDIT et BANK UTILITY grisés (voulu)
[ ] Avertissements macOS / Windows au lancement : souvent normaux

[ ] Un Matrix-6R peut s'afficher comme Matrix-6
