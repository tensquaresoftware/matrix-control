BIENVENUE
--------------------------------------------------------------------------------

Merci de participer aux tests bêta du Matrix-Control ! :)

Le Matrix-Control est un éditeur MIDI moderne pour les synthétiseurs Oberheim
Matrix-1000, Matrix-6 et Matrix-6R. Utilisable en application autonome ou en
plugin VST3/AU, il sert de « télécommande » à l'écran : il envoie et reçoit des
messages MIDI (réglages, patches, master) pour que vous puissiez voir et
modifier le synthé plus confortablement. En revanche, il ne produit pas le son
et ne l'enregistre pas non plus — le flux audio sort toujours du synthétiseur.
Pour l'entendre, vous devrez brancher la sortie audio du synthé sur une entrée
de votre interface audio, votre table de mixage ou vos enceintes.

--------------------------------------------------------------------------------
À QUOI SERT CE GUIDE ?
--------------------------------------------------------------------------------

Ce document n'est pas un cours sur la synthèse sonore, ni le manuel utilisateur
complet du Matrix-Control. C'est un guide de TESTS : une liste de situations
concrètes à tester chez vous, pour vérifier que tout se comporte correctement
sur la version bêta du logiciel, avant la diffusion d'une version finale et
stable par le développeur. Vos retours (surtout les bugs et les moments de
confusion) sont très précieux !

Comment utiliser ce guide ?
---------------------------
Parcourez-le dans l'ordre. Après la phase de préparation (sections 1 à 3),
chaque section vous met en contexte, vous fait tester, puis vous demande de
renseigner les cases au fur et à mesure.

1. Ouvrez le guide dans un éditeur de texte basique (TextEdit sous macOS,
   Bloc-notes sous Windows, gedit sous Linux, etc.) et remplissez-le à
   l'écran. Évitez de l'imprimer : les cases et notes sont bien plus
   simples à renvoyer ensuite par mail sous forme de fichier texte.

2. Remplacez le caractère entre crochets selon le résultat obtenu (majuscule ou
   minuscule acceptée) :
     [ ]  point non encore traité
     [V]  succès (test = Vrai / Valid)
     [F]  échec (test = Faux / Failure)
     [?]  doute — test effectué, mais résultat peu clair ou ambigu
     [-]  point sans objet pour votre configuration
          (ex. plugin AU sous Windows, BANK UTILITY sur un Matrix-6/6R)

   En cas de [F] ou [?], précisez dans « Notes personnelles » (juste sous
   la section concernée) : message exact à l'écran, ce que vous attendiez,
   ce qui s'est passé. C'est l'endroit prévu pour le détail.

3. Vous n'irez peut-être pas jusqu'au bout des tests : c'est normal. La PARTIE A
   (tests essentiels) est la plus importante. Si vous vous arrêtez à la fin
   de la PARTIE A et passez au bilan (section 19) puis à l'envoi
   (section 20), vos retours sont déjà très utiles ! ;)

Deux rythmes dans le même guide
-------------------------------
- PARTIE A — Tests essentiels : sections 4 à 12 (environ 30 à 45 minutes).
  Arrêt possible ensuite → PARTIE C (bilan + envoi).
- PARTIE B — Tests approfondis : sections 13 à 17 (suite optionnelle pour
  un parcours complet). Avec A + B, vous avez fait un parcours complet.
- PARTIE C — Fin de session : points connus, bilan, envoi des résultats.

Une seule combinaison ordinateur + logiciel de MAO (DAW) + synthé Oberheim +
éditeur Matrix-Control suffit déjà à être utile. Si vous pouvez tester sur
plusieurs modèles de synthés, tant mieux — mais ce n'est pas obligatoire.


À propos des noms affichés à l'écran
------------------------------------
L'interface graphique (GUI) du Matrix-Control est uniquement en anglais. Dans ce
guide, les noms des écrans et boutons restent donc en anglais, comme vous les
voyez : GETTING STARTED, PATCH EDIT, BANK UTILITY, etc. Le reste du texte est
en français dans ce guide, pour mieux vous accompagner.

Repère rapide dans la fenêtre principale
----------------------------------------
Une fois le logiciel ouvert, l'interface utilisateur ou « GUI » s'organise à peu
près ainsi :

+--------------------------------------------------------------------+
| Logo MATRIX-CONTROL | Undo/Redo, LEDs MIDI (FROM/TO SYNTH, etc.)   | <- HEADER
+--------------------------------------------------------------------+
|                     |                        |                     |
| PATCH EDIT          | MATRIX MODULATION      | MASTER EDIT         |
| - 10 modules son :  | (10 bus de modulation) | (Matrix-1000        |
|   DCO, VCF, ENV…    |------------------------|  uniquement ; grisé |
| - 5 afficheurs :    | PATCH MANAGER          |  sur Matrix-6/6R)   | <- BODY
|   - 3 Enveloppes    | - INTERNAL PATCHES     |                     |
|   - 1 Track Gen.    | - COMPUTER PATCHES     |                     |
|   - 1 PATCH NAME    | - BANK UTILITY         |                     |
|                     | - PATCH MUTATOR        |                     |
+--------------------------------------------------------------------+
| Messages/aide utilisateur            Badge DEVICE (type de synthé) | <- FOOTER
+--------------------------------------------------------------------+

Vocabulaire utile (aligné sur le manuel utilisateur) :
- Fenêtre = la fenêtre principale du Matrix-Control, ou une fenêtre qui
  s'ouvre par-dessus (SETTINGS, ABOUT)
- Panneau = grandes régions de la fenêtre principale (HEADER, BODY, FOOTER)
- Section = grand bloc à l'intérieur du panneau BODY (PATCH EDIT, MATRIX
  MODULATION, PATCH MANAGER, MASTER EDIT)
- Module = bloc à l'intérieur d'une section (DCO 1, DCO 2, INTERNAL PATCHES,
  PATCH MUTATOR, MIDI, VIBRATO, MISC, BANK UTILITY, etc.)
- Groupe = sous-partie d'un module (BROWSER, MEMORY, STORAGE, etc.)
- Bus de modulation = une des dix lignes de la section MATRIX MODULATION
- Dialogue = petite boîte de confirmation/choix utilisateur (UNSAVED PATCH,
  RESET MASTER MODULE?, alertes du PATCH MUTATOR, etc.)

Un manuel utilisateur plus détaillé sera fourni à terme avec le Matrix-Control ;
ce guide de tests ne le remplace pas.

1. CE DONT VOUS AUREZ BESOIN POUR TESTER LE MATRIX-CONTROL
================================================================================

Cette section est une checklist « Suis-je prêt ? ». Indiquez avec [V] ce
dont vous disposez, [-] si le point est sans objet, ou laissez [ ] s'il
est non traité. Les détails de votre configuration (quel Mac / PC, quelle
version d'OS, quel DAW, quel synthé exact, etc.) se notent dans la fiche
d'identification de votre session (section 3).

--------------------------------------------------------------------------------
1.1. Synthétiseur
--------------------------------------------------------------------------------
Au moins un synthétiseur Oberheim compatible avec le Matrix-Control :
[ ] Matrix-1000 : idéal pour couvrir presque tout le guide et les tests, y
    compris les banques et les réglages globaux « Master »
[ ] Matrix-6 / Matrix-6R : très utile également, certaines zones du logiciel
    seront volontairement grisées — c'est normal

--------------------------------------------------------------------------------
1.2. Ordinateur
--------------------------------------------------------------------------------
[ ] Un ordinateur équipé de l'un des systèmes d'exploitation supportés :
    macOS (Apple Silicon ou Intel), Windows 10 ou 11, ou Linux
    (Ubuntu 24.x / 26.x ou proche)

--------------------------------------------------------------------------------
1.3. Accessoires
--------------------------------------------------------------------------------
[ ] Une interface MIDI (boîtier USB-MIDI, ou interface audio équipée de
    connecteurs MIDI au format DIN 5 broches), avec deux câbles MIDI pour une
    connexion dans les DEUX sens (ordinateur ↔ synthé). Le branchement concret
    se fait en section 5.
[ ] Un chemin audio pour entendre le synthé (sortie du synthé vers une
    entrée d'interface audio, table de mixage ou enceintes). Le
    Matrix-Control pilote uniquement le synthé en MIDI : il n'enregistre
    pas le son et ne le remplace pas.

--------------------------------------------------------------------------------
1.4. Logiciels
--------------------------------------------------------------------------------
[ ] Le fichier ZIP du Matrix-Control fourni pour la bêta (il n'y a pas
    d'installateur : vous copierez les fichiers à la main — la section 4
    explique comment). Le ZIP contient aussi une documentation et un
    dossier de données de tests (Patches & Masters) — détail en section 4.1.
[ ] Un éditeur de texte basique pour renseigner ce guide au fur et à mesure
[ ] Soit un logiciel de MAO (DAW) pour tester le plugin VST3/AU
    (Ableton Live, Bitwig Studio, Logic Pro, Cubase, Reason, Reaper, etc.),
    soit uniquement l'application autonome (Standalone) du Matrix-Control

================================================================================
2. POINTS IMPORTANTS AVANT DE COMMENCER
================================================================================

Ces points évitent de confondre des comportements voulus ou des messages
habituels sous macOS / Windows, avec des bugs.

--------------------------------------------------------------------------------
2.1. Distribution en fichier ZIP
--------------------------------------------------------------------------------
Dans sa version bêta, le Matrix-Control est livré dans une archive ZIP,
sans assistant d'installation. Vous extrayez le ZIP, puis vous copiez
vous-même l'application et/ou les plugins aux endroits habituels de
votre système (détail en section 4). Il n'y a donc pas encore d'assistant
classique du type « Lancer > Suivant > Suivant > ... > Terminer » : ce n'est pas
un oubli.

--------------------------------------------------------------------------------
2.2. Messages de sécurité de macOS ou Windows
--------------------------------------------------------------------------------
Les fichiers exécutables de la bêta ne passent pas encore par la certification
payante d'Apple (« notarisation ») ni par la signature éditeur Microsoft
Windows.

Résultat fréquent et NORMAL :
- sous macOS : avertissement du type « développeur non identifié » ;
- sous Windows : écran SmartScreen du type « Windows a protégé votre PC ».

Ce n'est en général PAS un virus ni un bug du plugin. La section 4 explique
comment continuer en confiance (par exemple clic droit → Ouvrir sous macOS).

--------------------------------------------------------------------------------
2.3. Écoute audio dans l'application Standalone sous Windows (ASIO)
--------------------------------------------------------------------------------
En mode Standalone (application autonome, hors DAW), le Matrix-Control peut
écouter le retour audio de votre synthé via l'interface audio connectée à votre
ordinateur. Sous Windows, cela passe souvent par le pilote audio du système
(parfois appelé WASAPI).

À terme, le Matrix-Control devrait également proposer l'ASIO : un pilote très
utilisé en MAO, en général plus réactif (latence plus faible). Pour l'instant,
l'ASIO peut encore être absent des premières versions bêta : le développeur
attend un accord de licence avec Steinberg, l'éditeur et propriétaire de
cette technologie. Si vous ne voyez pas ASIO dans la liste audio, ce n'est
donc pas un bug : notez-le, et vérifiez surtout que l'écoute marche avec le
pilote système. L'essentiel reste d'entendre le synthé et de pouvoir l'éditer.

--------------------------------------------------------------------------------
2.4. Protégez vos patches internes avant de démarrer les tests
--------------------------------------------------------------------------------
Certaines étapes écrivent dans la mémoire du synthé (STORE, variations du
PATCH MUTATOR, transferts de banques). Si vous tenez à des patches déjà
présents dans votre Matrix-1000/6/6R, sauvegardez-les d'abord sur
l'ordinateur, une fois le Matrix-Control installé (section 4) et le synthé
détecté (section 7).

Méthode prévue dans ce guide : module COMPUTER PATCHES (section PATCH
MANAGER) → bouton SAVE AS → fichiers .syx (un fichier par patch). Un rappel
concret est placé juste avant les tests d'écriture (section 12). Le parcours
complet des fichiers (y compris les dossiers fournis dans le ZIP) est en
section 13.

--------------------------------------------------------------------------------
2.5. Si STORE semble ne pas enregistrer
--------------------------------------------------------------------------------
Sur un Matrix-1000, une protection mémoire ou un verrouillage de banque
(MEMORY PROTECT / BANK LOCK, sur la machine ou dans la section MASTER EDIT)
peut empêcher l'écriture des patches.

Sur un Matrix-6/6R, vérifiez surtout l'interrupteur Memory Protect situé
à l'arrière de la machine (à mettre sur Off pour pouvoir enregistrer), et
éventuellement la protection par patch sur la façade. Ces réglages ne
sont pas éditables dans le Matrix-Control (MASTER EDIT est grisé).

Vérifiez cela avant de conclure à un bug.

4. INSTALLER LE MATRIX-CONTROL
================================================================================

Dans sa version bêta, le Matrix-Control est fourni sans assistant
d'installation. Vous devez donc extraire l'archive ZIP, copier les fichiers
exécutables aux endroits indiqués, puis éventuellement demander à votre DAW de
rescanner la liste des plugins.

L'objectif ici est d'installer les fichiers et de vérifier que le logiciel peut
s'ouvrir (messages de sécurité compris).

Si l'assistant GETTING STARTED du Matrix-Control s'ouvre déjà :
choisissez CONFIGURE LATER, puis continuez l'installation.

--------------------------------------------------------------------------------
4.1. Contenu de l'archive ZIP
--------------------------------------------------------------------------------
Selon votre système, vous devriez trouver au moins :

[ ] Un dossier d'exécutables (application autonome + plugins), selon votre
    système d'exploitation
[ ] L'application autonome (Standalone)
[ ] Le plugin VST3
[ ] Sur macOS seulement : le plugin AU
[ ] Un dossier Documentation/ (ce guide de tests ; Matrix-Control-Comment-
    signaler-un-bug-FR.txt pour les bugs hors campagne ; éventuellement un
    manuel)
[ ] Un dossier Test-Data/ avec des fichiers de test prêts à l'emploi :
      Test-Data/Patches/syx/     — patches .syx (+ invalid-*.syx)
      Test-Data/Patches/m1kp/    — patches .m1kp (+ invalid-*.m1kp)
      Test-Data/Masters/syx/     — Masters .syx (+ invalid-*.syx)
      Test-Data/Masters/m1km/    — Masters .m1km (+ invalid-*.m1km)
    Les fichiers dont le nom commence par « invalid- » sont volontairement
    incorrects : ils servent aux tests de refus / message « N valid,
    M invalid » (section 13). Ces dossiers servent surtout à partir de
    la section 13.

Si quelque chose manque, notez le nom exact du fichier ZIP et ce qui est absent.

--------------------------------------------------------------------------------
4.2. Tester sous macOS
--------------------------------------------------------------------------------

Cette section concerne macOS sur processeur Apple Silicon ou Intel.

4.2.1. Copier les fichiers
--------------------------
Où copier (le signe ~ désigne votre dossier personnel, ex. /Users/VotreNom) :

  Plugin AU   →  ~/Library/Audio/Plug-Ins/Components/
  Plugin VST3 →  ~/Library/Audio/Plug-Ins/VST3/
  Application →  /Applications/
                 (ou à côté du ZIP, si vous préférez)

Dans le Finder, le dossier Library de votre compte est souvent masqué :
menu Aller → Aller au dossier…, puis collez le chemin ci-dessus.

[ ] Extraire le ZIP
[ ] Copier Matrix-Control.component dans Components
[ ] Copier Matrix-Control.vst3 dans VST3
[ ] (Optionnel) Copier Matrix-Control.app dans Applications

4.2.2. Lever le drapeau de quarantaine (Terminal)
-------------------------------------------------
Après un téléchargement navigateur / GitHub, macOS peut afficher que l'app
ou le plugin est « endommagé » / « damaged ». Il faut alors lever le
« drapeau de quarantaine » une fois, avec le Terminal :

1. Ouvrir « Terminal » :
   - Raccourci : Commande (⌘) + barre d'espace → Spotlight → taper
     Terminal → Entrée.
   - Ou : Finder → Applications → Utilitaires → Terminal.
2. Dans le Terminal, taper exactement ceci, puis un espace (ne validez
   pas encore) :

     xattr -cr

3. Dans le Finder, glisser-déposer sur la fenêtre Terminal chacun des
   fichiers copiés (Matrix-Control.app, Matrix-Control.vst3,
   Matrix-Control.component). macOS écrit le chemin tout seul. Séparez
   les fichiers par un espace. Omettez ce que vous n'avez pas installé.
4. Quand la ligne ressemble à ceci (vos chemins peuvent différer) :

     xattr -cr /Applications/Matrix-Control.app \
               ~/Library/Audio/Plug-Ins/VST3/Matrix-Control.vst3 \
               ~/Library/Audio/Plug-Ins/Components/Matrix-Control.component

   appuyez sur Entrée. En général, le Terminal n'affiche rien de plus si
   la commande a réussi — c'est normal.
5. Quitter le Terminal : menu Terminal → Quitter Terminal, ou ⌘Q.
   Vous n'en aurez plus besoin pour la suite de ce guide.

Variante sans glisser-déposer : copier la commande d'exemple (⌘C), coller
dans Terminal (⌘V), adapter les chemins, puis Entrée.

[ ] La commande xattr a été exécutée sans message d'erreur

4.2.3. Premier lancement et rescan dans le DAW
----------------------------------------------
[ ] Premier lancement : si macOS dit « développeur non identifié »,
    clic droit → Ouvrir, ou autoriser dans Réglages Système.
    C'est attendu pour cette bêta. Ce n'est pas un bug.
[ ] Lancer le Standalone : la fenêtre s'ouvre
    Si GETTING STARTED apparaît : CONFIGURE LATER
[ ] Dans le DAW : ouvrez les préférences / réglages, section Plugins /
    Audio Units / VST (le nom varie selon le logiciel). Lancez un rescan
    ou une actualisation de la liste (bouton du type « Rescan », « Scan »,
    « Actualiser » ou « Reset & Rescan »). Sans cette étape, le plugin
    peut être bien copié sur le disque mais invisible dans la liste.
[ ] Le Matrix-Control apparaît en AU et/ou VST3
[ ] Charger le plugin sur une piste instrument / MIDI

Ce qui est normal :
- l'appli et les plugins démarrent ;
- après xattr, plus de message « endommagé » / « damaged » en principe ;
- un avertissement « développeur non identifié » peut encore apparaître :
  clic droit → Ouvrir.

4.3. Tester sous Windows
--------------------------------------------------------------------------------

Cette section concerne Windows 10 ou Windows 11.

4.3.1. Copier les fichiers
--------------------------
Où copier les fichiers :

  Plugin VST3 →  C:\Program Files\Common Files\VST3\
                 (emplacement souvent réservé aux administrateurs)
  Standalone  →  Matrix-Control.exe (où vous voulez)

[ ] Extraire le ZIP
[ ] Copier Matrix-Control.vst3 vers le dossier VST3 indiqué plus haut
    (C:\Program Files\Common Files\VST3\).

    Si Windows refuse la copie (message du type « vous devez être
    administrateur » ou « accès refusé »), ce n'est pas bloquant.
    Choisissez l'une de ces alternatives :

    A. Dossier VST3 de votre compte utilisateur — créez par exemple :

         C:\Users\VotreNom\Documents\VST3\

       (remplacez VotreNom par le nom de votre session Windows), puis
       copiez Matrix-Control.vst3 dedans.

    B. Un dossier « plugins » déjà utilisé par votre DAW — certains
       logiciels (Ableton Live, Bitwig Studio, Cubase, Reason, Reaper,
       etc.) ont leur propre dossier de plugins, ou permettent d'en
       ajouter un dans leurs préférences.

4.3.2. Premier lancement et SmartScreen
---------------------------------------
[ ] Lancer Matrix-Control.exe (double-clic) : la fenêtre s'ouvre.
    Si GETTING STARTED apparaît : choisissez CONFIGURE LATER
[ ] Si Windows affiche SmartScreen (« Windows a protégé votre PC ») :

    C'est attendu pour cette bêta : le fichier n'a pas encore la signature
    payante d'un éditeur Windows. Ce n'est en général PAS un virus.

    1. Sur l'écran bleu / sombre SmartScreen, cliquez
       « Informations complémentaires » (lien souvent en bas à gauche,
       facile à manquer).
    2. Un bouton « Exécuter quand même » apparaît : cliquez dessus.
    3. Si Windows demande une confirmation administrateur, acceptez.

    Si vous ne voyez que « Ne pas exécuter » sans le lien supplémentaire,
    agrandissez la fenêtre ou cherchez « Informations complémentaires »
    avant d'abandonner.

4.3.3. Rescan dans le DAW
-------------------------
[ ] Ouvrez les préférences / options du DAW, section Plugins / VST /
    VST3. Si vous avez choisi le dossier A ou B ci-dessus, ajoutez-le
    s'il n'y est pas déjà. Lancez un rescan (bouton du type « Rescan »,
    « Scan » ou « Actualiser »). Sans cette étape, le Matrix-Control
    peut être bien copié sur le disque mais invisible dans la liste.
[ ] Charger le Matrix-Control sur une piste instrument / MIDI

Sous Windows, un port MIDI est souvent réservé à une seule application à
la fois. Si le port refuse de s'ouvrir plus tard, voyez la section 7.3.

Ce qui est normal :
- Standalone et VST3 démarrent ;
- le plugin apparaît après un rescan dans le DAW ;
- SmartScreen peut réapparaître au premier lancement : même procédure.

4.4. Tester sous Linux
--------------------------------------------------------------------------------

Cette section concerne Linux, en pratique Ubuntu 24 / 26 ou une distribution
proche.

4.4.1. Copier les fichiers
--------------------------
Où copier les fichiers :

  Plugin VST3 →  ~/.vst3/
                 (dossier « .vst3 » dans votre dossier personnel ; le ~
                 = dossier personnel ; le point au début signifie qu'il
                 est souvent masqué dans le gestionnaire de fichiers)
  Standalone  →  binaire nommé Matrix-Control (ou proche) fourni dans le ZIP
                 — placez-le où vous voulez (Bureau, Applications, etc.)

[ ] Extraire le ZIP (clic droit → Extraire ici, ou double-clic selon
    votre gestionnaire d'archives)
[ ] Créer le dossier du plugin s'il n'existe pas encore, puis y copier
    Matrix-Control.vst3.

    Méthode avec le gestionnaire de fichiers (Nautilus sous Ubuntu) :
    1. Ouvrez votre dossier personnel (Maison / Home).
    2. Affichez les fichiers cachés : Ctrl+H (ou menu Affichage →
       Afficher les fichiers cachés).
    3. Si le dossier « .vst3 » n'existe pas : clic droit → Nouveau dossier,
       nommez-le exactement .vst3 (avec le point).
    4. Copiez Matrix-Control.vst3 depuis le ZIP extrait vers ce dossier

    Variante en ligne de commande (si vous préférez) : ouvrir le Terminal
    (touche Super / Windows, taper Terminal, Entrée), puis :

      mkdir -p ~/.vst3
      cp /chemin/vers/Matrix-Control.vst3 ~/.vst3/

    Remplacez /chemin/vers/… en glissant le fichier .vst3 depuis le
    gestionnaire de fichiers vers le Terminal après avoir tapé « cp »
    et un espace.

4.4.2. Rendre le Standalone exécutable
--------------------------------------
[ ] Si Linux refuse de lancer le Standalone (« Permission denied »,
    icône grisée, ou rien ne se passe) :

    1. Ouvrir le Terminal.
    2. Taper exactement ceci, puis un espace (ne validez pas encore) :

         chmod +x

    3. Glisser-déposer le fichier Matrix-Control (Standalone) depuis le
       gestionnaire de fichiers vers le Terminal : le chemin s'écrit
       tout seul.
    4. Appuyer sur Entrée. En général, rien ne s'affiche si la commande
       a réussi — c'est normal.
    5. Quitter le Terminal (fermer la fenêtre suffit).

4.4.3. Premier lancement, rescan DAW et audio
---------------------------------------------
[ ] Lancer le Standalone :
    - double-clic sur le fichier dans le gestionnaire de fichiers, ou
    - depuis le Terminal, pour voir d'éventuels messages d'erreur :

         /chemin/vers/Matrix-Control

      (glisser le fichier dans le Terminal après avoir préparé la ligne,
      puis Entrée)
    Si GETTING STARTED apparaît : CONFIGURE LATER
[ ] Dans le DAW : ouvrez les préférences, section Plugins / VST3, lancez
    un rescan / actualisation. Le Matrix-Control doit apparaître.
    Chargez-le sur une piste instrument / MIDI.
[ ] Ouvrir SETTINGS → AUDIO et noter ce qui est proposé (noms de
    périphériques, pilotes système type ALSA / PulseAudio / PipeWire,
    éventuellement JACK). Pas besoin de tout comprendre : l'idée est de
    savoir quel chemin audio Linux vous propose, pour le noter dans la
    fiche de session (section 3) si un problème audio apparaît plus tard.

Ce qui est normal :
- le Standalone et le VST3 démarrent ;
- aucun message bloquant du type « bibliothèque manquante »
  (shared library / .so introuvable) ;
- si un tel message apparaît quand même, copiez-le mot pour mot dans
  les notes — c'est utile pour le développeur.

7. VÉRIFIER LA COMMUNICATION MIDI
================================================================================

C'est l'étape la plus importante côté logiciel. Tant que le synthé n'est
pas reconnu sur le réseau MIDI, une grande partie de l'éditeur reste
verrouillée — c'est voulu, pour éviter d'envoyer des changements « à
l'aveugle ».

--------------------------------------------------------------------------------
7.1. Choisir ou confirmer les ports MIDI
--------------------------------------------------------------------------------
[ ] Réglez ou vérifiez SYNTH FROM et SYNTH TO (bandeau FROM SYNTH /
    TO SYNTH, ou SETTINGS → MIDI & DEVICE)
[ ] Quand du MIDI circule, les LEDs à côté des listes clignotent
[ ] En bas à droite, le badge DEVICE affiche Matrix-1000, Matrix-6, etc.
    (un Matrix-6R peut apparaître comme Matrix-6 : notez-le si c'est le cas)
[ ] Si NOT CONNECTED : suivez le message en bas de fenêtre
    (câbles — section 5 —, ports, éteindre/rallumer le synthé)

--------------------------------------------------------------------------------
7.2. Édition verrouillée puis débloquée
--------------------------------------------------------------------------------
[ ] Sans détection correcte, l'édition reste verrouillée (normal)
[ ] Une fois le synthé reconnu, PATCH EDIT et les zones utiles se débloquent

--------------------------------------------------------------------------------
7.3. Sous Windows : cas des ports MIDI déjà occupés
--------------------------------------------------------------------------------
Sous Windows, un port MIDI est souvent réservé à une seule application à
la fois.

[ ] Si le port refuse de s'ouvrir : fermez l'autre application / DAW qui
    l'occupe, puis réessayez
[ ] Résultat attendu : DEVICE reconnu, édition possible, pas de cascade
    d'erreurs si les ports sont bons.

--------------------------------------------------------------------------------
7.4. Version du Matrix-Control et type d'EPROM
--------------------------------------------------------------------------------

Quand le synthé est reconnu, regardez dans SETTINGS → MIDI & DEVICE (liste
EPROM TYPE, et éventuellement le badge DEVICE en bas à droite).

Sur un Matrix-1000 : le Matrix-Control peut interroger la machine en MIDI
(Device Inquiry) et proposer un type d'EPROM / firmware d'après la version
renvoyée. Notez ce qui s'affiche — surtout si cela diffère de ce que vous
pensiez avoir. Si la liste indique UNKNOWN, notez-le aussi.

Sur un Matrix-6/6R : en pratique, cette interrogation de version n'est en
général pas disponible. Le logiciel peut quand même reconnaître la famille
Matrix-6 via un autre échange MIDI, sans obtenir le type d'EPROM.
Choisissez alors EPROM TYPE vous-même si besoin, ou laissez UNKNOWN si
vous n'êtes pas sûr — et notez ce que vous voyez.
(Rappel : un Matrix-6R peut s'afficher comme Matrix-6 — voir section 7.1.)

(logo MATRIX-CONTROL → ABOUT…, ou message / page du téléchargement)

8. TESTER L'APPLICATION AUTONOME ET LE PLUGIN
================================================================================

Le Matrix-Control peut s'utiliser de deux façons :
- application autonome (Standalone), sans DAW ;
- plugin dans le DAW (VST3 sous macOS, Windows et Linux ; AU en plus
  sous macOS).

--------------------------------------------------------------------------------
8.1. En plugin
--------------------------------------------------------------------------------
[ ] Le plugin se charge sans planter
[ ] Les notes MIDI arrivent via la piste du DAW (KEYBOARD FROM = HOST)
[ ] Le son du synthé revient sur une piste audio séparée
    (le plugin ne génère pas l'audio du synthé)
[ ] GETTING STARTED n'impose pas d'étape intitulée « Step 4: Audio »
[ ] SETTINGS… est accessible (logo MATRIX-CONTROL ou raccourci)

--------------------------------------------------------------------------------
8.2. En Standalone
--------------------------------------------------------------------------------
[ ] La fenêtre autonome s'ouvre ; SETTINGS → AUDIO est disponible
[ ] Vous entendez le retour du synthé via l'interface audio choisie
[ ] KEYBOARD FROM est sélectionnable (ou SKIP dans GETTING STARTED)
[ ] Si INPUT GAIN / monitoring apparaît dans le bandeau : il réagit

--------------------------------------------------------------------------------
8.3. Écoute audio sous Windows (Standalone)
--------------------------------------------------------------------------------

Contexte ASIO / WASAPI : voir section 2.3. Ici, on vérifie seulement
l'écoute pendant les tests.

[ ] Avec le pilote système (souvent WASAPI) : l'entrée est audible et la
    latence est acceptable pour éditer
[ ] Si ASIO apparaît dans la liste : le périphérique est sélectionnable et
    l'audio fonctionne
[ ] Si ASIO n'apparaît pas : notez-le et continuez avec le pilote système
    — ce n'est pas forcément un échec pour cette première bêta (section 2.3)

[ ] Résultat attendu : plugin et Standalone utilisables ; au minimum, écoute
    Standalone via les pilotes système.

--------------------------------------------------------------------------------
8.4. Parité AU et VST3 (macOS seulement)
--------------------------------------------------------------------------------

Sur macOS, si vous avez installé AU et VST3, vérifiez qu'ils se comportent
de la même façon sur l'essentiel (pas besoin de tout retester deux fois).

[ ] Les deux formats se chargent dans le DAW sans plantage
[ ] Dans chaque format : le badge DEVICE reconnaît le même synthé (mêmes
    ports MIDI / même détection)
[ ] Dans chaque format : un même geste d'édition simple (ex. coupure VCF)
    change le son de façon audible
[ ] SETTINGS… s'ouvre depuis le logo dans les deux formats
[ ] Notez toute différence gênante (détection, édition, messages) — ce
    serait utile même si le reste du guide a été fait surtout en VST3
    ou en Standalone

Sous Windows / Linux : indiquez [-] (pas de format AU disponible).

9. ABLETON LIVE ET IMAGE FLOUE SOUS WINDOWS
================================================================================

Ce problème concerne uniquement les utilisateurs sous Windows + Ableton Live +
plugin VST3 du Matrix-Control.

Problème connu : sous Windows, Live propose une option « Auto-Scale Plugin
Window ». Quand elle est activée, l'interface graphique du Matrix-Control peut
apparaître floue dans le plugin VST3, quel que soit le UI Scale. L'application
Standalone reste nette sur la même machine. Sous macOS, cette option n'existe
pas dans Live, et donc en principe le problème ne se pose pas.

Comment désactiver l'option :
[ ] Chargez d'abord le Matrix-Control sur une piste dans Live
[ ] Faites un clic droit sur la barre de titre du device (en bas, dans la vue
    Device) → désactiver « Auto-Scale Plugin Window »
[ ] Rechargez le device
[ ] Vérifiez que l'interface VST3 est nette
[ ] Comparez avec le Standalone (doit rester net)

10. ÉDITER UN PATCH
================================================================================

Si quelque chose vous surprend pendant l'édition (Unison, mode clavier,
STORE, etc.), consultez aussi la section 18 (Points connus à vérifier) —
ce ne sont pas toujours des bugs.

Une fois le synthé détecté, chargez un patch via le module INTERNAL PATCHES
(dans la section PATCH MANAGER — détail section 12), puis travaillez dans
la section PATCH EDIT.

Chaque mouvement à l'écran est envoyé au synthé : vous devez entendre le
changement sur la machine.

Modules présents dans la section PATCH EDIT :
- DCO 1 / DCO 2     Oscillateurs
- VCF/VCA           Filtre et amplificateurs
- FM/TRACK          FM + Track Generator (+ afficheur)
- RAMP/PORTAMENTO   Rampes, portamento, mode clavier
- ENV 1/2/3         Enveloppes multi-segments (+ afficheurs)
- LFO 1 / LFO 2     Oscillateurs basse fréquence
- PATCH NAME        Nom du patch (8 caractères)

--------------------------------------------------------------------------------
10.1. Gestes représentatifs
--------------------------------------------------------------------------------
[ ] Dans le module DCO 1, changez un paramètre (forme d'onde, désaccordage,
    etc.) : le son change
[ ] Dans le module VCF/VCA, bougez la fréquence de coupure et/ou la résonance
    du filtre : le son change
[ ] Sur une enveloppe (module ENV), déplacez un point à la souris : le son
    ou l'affichage réagit
[ ] Dans le module FM/TRACK, déplacez un point du Track Generator à la
    souris : le son ou l'affichage réagit

--------------------------------------------------------------------------------
10.2. Sliders et listes : clavier et édition fine
--------------------------------------------------------------------------------

Prenez un slider numérique typique (ex. fréquence de coupure VCF) : cliquez
d'abord dessus pour lui donner le focus (contour / surbrillance).

[ ] Flèches haut / droite : la valeur augmente d'un pas
[ ] Flèches bas / gauche : la valeur diminue d'un pas
[ ] Shift + flèches : la valeur bouge par pas de 10
[ ] Cmd+clic (macOS) ou Ctrl+clic (Windows / Linux) : le slider est réinitialisé
    à sa valeur par défaut
[ ] Double-clic sur le slider : un champ d'édition s'ouvre ; tapez une
    valeur, validez (Entrée) — la valeur et le son suivent
[ ] Sur une liste déroulante (combo), donnez-lui le focus puis utilisez
    les flèches haut / bas : le choix change sans ouvrir le menu (ou de
    façon claire) ; notez le comportement exact

--------------------------------------------------------------------------------
10.3. Boutons I / C / P sur un module
--------------------------------------------------------------------------------
Sur plusieurs modules, l'en-tête propose :
  I = Init   (réinitialise le module à des valeurs par défaut)
  C = Copy   (copie le module vers le presse-papiers)
  P = Paste  (colle le module depuis le presse-papiers)

[ ] I réinitialise le module
[ ] C puis P sur un module compatible fonctionne
[ ] Sur un module incompatible, P est grisé ; un clic peut afficher un
    message dans le FOOTER (en bas à gauche dans la fenêtre)

--------------------------------------------------------------------------------
10.4. Annuler / rétablir
--------------------------------------------------------------------------------
[ ] Annuler (Cmd+Z sous macOS, Ctrl+Z sous Windows/Linux) revient en arrière
[ ] Rétablir (Cmd+Shift+Z / Ctrl+Shift+Z) restaure la dernière opération
[ ] Charger un autre patch efface cet historique d'annulation

--------------------------------------------------------------------------------
10.5. Nom du patch
--------------------------------------------------------------------------------

Le nom s'affiche et s'édite dans le champ PATCH NAME (8 caractères).

Sur un Matrix-1000, les banques 0 et 1 sont réinscriptibles ; les banques
2 à 9 sont des mémoires d'usine en lecture seule (renommer / STORE /
INIT / PASTE y sont bloqués — rappelé aussi en sections 12 et 15).

[ ] L'afficheur PATCH NAME montre le nom actuel (8 caractères)
[ ] Matrix-1000, banques 0 et 1 : double-clic pour renommer ouvre l'édition
[ ] Matrix-1000, banques 2 à 9 : double-clic ne permet pas de renommer
    (champ bloqué / pas d'édition)
[ ] Matrix-6/6R : double-clic pour renommer fonctionne (toutes les mémoires
    sont réinscriptibles)
[ ] Le nom se met aussi à jour au chargement d'un patch ou après certaines
    actions du PATCH MUTATOR

[ ] Résultat attendu : édition audible ; sliders / listes au clavier OK ;
    annulation cohérente ; pas de fermeture intempestive.

11. ÉDITER LA MATRICE DE MODULATION
================================================================================

Cette matrice est le « câblage » interne du synthé : on relie une source (LFO,
enveloppe, vélocité, etc.) à une destination (filtre, hauteur, etc.). Dix bus,
numérotés de 0 à 9, sont affichés sous forme de lignes de programmation à
l'écran.

Préparez : synthé détecté, un patch chargé.
Choisissez une modulation facile à entendre : ce n'est pas toujours
évident selon la combinaison. Exemples : moduler le filtre ou le pitch
avec une enveloppe, un LFO, etc.

[ ] Sur un bus, réglez SOURCE, AMOUNT et DESTINATION (autre que NONE)
[ ] Jouez une note : la modulation s'entend / se sent
[ ] Le bouton I sur un bus remet ce bus à zéro
[ ] Le bouton I de la section MATRIX MODULATION réinitialise tous les bus
[ ] Si C / P existent au niveau de la section MATRIX MODULATION : copier /
    coller un bus (ou la section) se comporte de façon claire
[ ] Réordonnez deux bus en glissant le numéro # : le bus de départ apparaît en
    gris, le bus d'arrivée en rouge ; les contenus des bus s'échangent, les
    numéros restent ordonnés de 0 à 9
[ ] Annuler après ce réordonnancement revient d'une étape

[ ] Résultat attendu : bus éditables, réordonnancement stable.

12. GÉRER LES PATCHES DANS LA MÉMOIRE DU SYNTHÉ
================================================================================

Dans la section PATCH MANAGER, le module INTERNAL PATCHES pilote la
mémoire du synthétiseur (banque / numéro selon la machine).

Focus de navigation : un seul module à la fois « tient » les boutons
< / > et la navigation patch. Cliquez le titre INTERNAL PATCHES pour
lui donner ce focus (le titre passe en rouge). Au survol, le titre
réagit aussi (changement de couleur) pour indiquer qu'il est cliquable.
Le même principe vaut pour COMPUTER PATCHES (fichiers .syx — section 13) :
cliquer l'un ou l'autre alterne entre mémoire interne et fichiers.

Avant STORE / INIT / PASTE : si vos patches actuels vous sont précieux et
que vous ne les avez pas encore sauvés sur le disque, faites-le maintenant.
Module COMPUTER PATCHES → SAVE AS → un fichier .syx par patch important.
(Le test détaillé des fichiers, y compris Test-Data/ du ZIP, est en
section 13 — vous pouvez y passer un instant, puis revenir ici.)

--------------------------------------------------------------------------------
12.1. Navigation et STORE
--------------------------------------------------------------------------------

[ ] Survolez le titre INTERNAL PATCHES : le titre réagit (couleur)
[ ] Cliquez le titre INTERNAL PATCHES : le module prend le focus
    (titre en rouge)
[ ] Les boutons < et > changent de patch ; le Matrix-Control relit le patch
    depuis le synthé
[ ] Double-clic sur le numéro de patch : la saisie directe 0 à 99 fonctionne
[ ] STORE enregistre dans l'emplacement courant (Matrix-1000 : banques 0
    et 1 seulement — voir section 10.5)
[ ] Matrix-1000, banques 2 à 9 : INIT, PASTE et STORE sont grisés — c'est
    normal (mémoires d'usine)

--------------------------------------------------------------------------------
12.2. INIT / COPY / PASTE
--------------------------------------------------------------------------------

Ici, INIT / COPY / PASTE portent sur le patch entier (pas seulement un
module comme en section 10.3). Travaillez sur une banque réinscriptible
(Matrix-1000 : 0 ou 1) ou sur un Matrix-6/6R (mémoire réinscriptible).

[ ] INIT : le patch est réinitialisé conformément au modèle ; PATCH NAME doit
    afficher « * INIT * »
[ ] COPY puis PASTE vers un autre emplacement : le son et l'écran restent
    cohérents
[ ] Après PASTE, vous pouvez utiliser STORE pour figer dans la mémoire du
    synthé

--------------------------------------------------------------------------------
12.3. Dialogue UNSAVED PATCH
--------------------------------------------------------------------------------

[ ] Forcer le dialogue : modifier un paramètre, puis changer de numéro de
    patch (ou de banque) sans STORE ni SAVE — le dialogue UNSAVED PATCH
    apparaît (sauf si UNSAVED STATE = NEVER WARN dans SETTINGS)
[ ] Tester CANCEL : vous restez sur le patch courant, modifications
    conservées à l'écran
[ ] Refaire : DISCARD — les modifications sont abandonnées, la navigation
    continue
[ ] Refaire : STORE et/ou SAVE / SAVE AS selon les boutons proposés — les
    choix sont clairs, pas de perte silencieuse
[ ] Après DISCARD / STORE / SAVE : la suite de la navigation est cohérente

[ ] Résultat attendu : navigation fluide ; STORE / INIT / COPY / PASTE OK sur
    mémoire réinscriptible ; banques d'usine protégées ; UNSAVED PATCH
    compréhensible.

13. GÉRER LES PATCHES ET MASTERS DANS DES FICHIERS INFORMATIQUES
================================================================================

Dans la section PATCH MANAGER, le module COMPUTER PATCHES gère les patches
sous forme de fichiers sur le disque (un patch par fichier). La mémoire du
synthé reste traitée à part (section 12). Les fichiers Master se chargent
surtout via SETTINGS ou par glisser-déposer (Matrix-1000 uniquement).

Comme pour INTERNAL PATCHES : survolez puis cliquez le titre COMPUTER
PATCHES pour lui donner le focus de navigation (titre en rouge). Les
boutons < / > parcourent alors les fichiers du dossier ouvert, et non
plus la mémoire du synthé. Recliquez INTERNAL PATCHES pour revenir à la
mémoire interne.

Fichiers de test fournis : utilisez de préférence le dossier Test-Data/
du ZIP de la bêta (voir section 4.1) — Patches/syx, Patches/m1kp,
Masters/syx, Masters/m1km. Les fichiers « invalid-* » sont volontairement
incorrects (refus / comptage valid vs invalid).

Le Matrix-Control s'inspire largement du « Matrix-1000 Editor », un prototype
Max for Live sorti le 21 décembre 2020 — aujourd'hui dépassé par cette
version standalone + plugins VST3 / AU, bien plus complète :

https://maxforlive.com/library/device/6806/matrix-1000-editor

Ce prototype avait introduit des formats customisés : .m1kp (patches) et .m1km
(Masters). Le .m1km y incluait encore les Groups du Matrix-1000 ; le
Matrix-Control ne les reprend pas (peu utiles en pratique), tout en restant
capable de lire ces fichiers pour la rétrocompatibilité.

Formats pris en charge :
  .syx   — Format courant du Matrix-Control (Patches et Masters)
  .m1kp  — Patch legacy du Matrix-1000 Editor (rétrocompatibilité)
  .m1km  — Master legacy du Matrix-1000 Editor (rétrocompatibilité)

Dans ce guide, « nom nettoyé » signifie : le nom est adapté à un format de 8
caractères et aux caractères autorisés (accents / symboles interdits retirés ou
remplacés, longueur ramenée à 8 si besoin).

--------------------------------------------------------------------------------
13.1. Patches .syx et .m1kp (OPEN / SAVE / Parcours)
--------------------------------------------------------------------------------

[ ] Survolez puis cliquez le titre COMPUTER PATCHES : focus (titre rouge)
[ ] Cliquez le titre INTERNAL PATCHES, puis à nouveau COMPUTER PATCHES :
    le focus alterne bien entre mémoire interne et fichiers
[ ] OPEN : choisissez un dossier contenant des patches .syx et, si possible,
    au moins un .m1kp (ex. Test-Data/Patches/syx — qui contient aussi
    invalid-PATCH.syx — et …/m1kp avec invalid-Patch.m1kp ; ou un
    dossier où vous avez copié les deux formats)
[ ] Après OPEN sur un dossier qui mélange valides et invalid-* : un
    message en bas de fenêtre indique combien de fichiers sont valides
    et invalides (ex. « N valid, M invalid ») — notez le texte exact
[ ] Les patches .syx et .m1kp valides apparaissent dans la liste ; les
    invalid-* n'y figurent pas comme patches chargeables
[ ] Charger un .syx : le patch s'affiche et s'entend ; PATCH NAME est
    cohérent
[ ] Charger un .m1kp (Matrix-1000 Editor) : le patch se charge ; PATCH NAME
    suit le nom de fichier (nettoyé)
[ ] SAVE AS : créez un nouveau .syx ; après l'enregistrement, PATCH NAME
    affiche un nom conforme au nom de fichier (nettoyé, 8 caractères
    Matrix)
[ ] Puis SAVE : enregistrez à nouveau dans le fichier .syx déjà associé
[ ] Parcourir la liste avec < / > et recharger un .syx puis un .m1kp
[ ] Après avoir chargé un .m1kp, SAVE / SAVE AS écrit bien un .syx (le
    .m1kp d'origine n'est pas écrasé) — notez les dialogues éventuels

--------------------------------------------------------------------------------
13.2. Noms de patches : fichier vs SysEx
--------------------------------------------------------------------------------

À régler dans SETTINGS, liste COMPUTER PATCHES. Trois options :
DISPLAY SYSEX NAMES, DISPLAY FILE NAMES, ASK ONCE PER LOAD.

Pour comparer, chargez un .syx dont le nom de fichier diffère du nom
interne du patch (une fois nettoyés).

[ ] DISPLAY SYSEX NAMES : au chargement, PATCH NAME suit le nom interne ;
    pas de dialogue « Patch name mismatch »
[ ] DISPLAY FILE NAMES : au chargement, PATCH NAME suit le nom de fichier
    nettoyé ; pas de dialogue « Patch name mismatch »
[ ] ASK ONCE PER LOAD : si les noms diffèrent, le dialogue « Patch name
    mismatch » apparaît. Testez INTERNAL (garder le nom SysEx), FILENAME
    (prendre le nom de fichier nettoyé) et CANCEL (noter ce qui se passe
    — chargement annulé ou état précédent conservé)

--------------------------------------------------------------------------------
13.3. Masters .syx et .m1km (Matrix-1000 uniquement)
--------------------------------------------------------------------------------

Les Masters se chargent ou s'enregistrent depuis SETTINGS (UTILITY /
MASTER : LOAD, SAVE AS), ou par glisser-déposer sur la fenêtre.
Fichiers d'exemple : Test-Data/Masters/syx et …/m1km (y compris
invalid-Master.syx et invalid-Master.m1km).

Au chargement d'un .m1km, le dialogue « Load .m1km Master? » peut
proposer trois choix (le Matrix-Control n'édite pas les concepts de Groups /
cascade, mais le Matrix-1000 peut encore les utiliser) :
- MASTER SETTINGS ONLY — réglages Master classiques ; Groups / cascade
  du fichier sont remis à zéro côté machine ;
- FULL MASTER — même chose, en conservant aussi Groups / cascade tels
  qu'ils sont dans le fichier ;
- CANCEL — ne change rien au Master actuel.

[ ] SETTINGS → LOAD d'un Master .syx valide : le chargement fonctionne
[ ] SETTINGS → LOAD d'un Master .m1km valide (Matrix-1000 Editor) : le
    dialogue ci-dessus apparaît ; testez au moins MASTER SETTINGS ONLY
    et FULL MASTER — chaque choix est clair ; notez ce que vous voyez
    (et CANCEL si vous voulez vérifier qu'il ne change rien)
[ ] SETTINGS → LOAD d'un invalid-Master.syx ou invalid-Master.m1km :
    refus ou message clair, pas de plantage
[ ] SETTINGS → SAVE AS d'un Master : un fichier est créé (en pratique
    .syx) et peut être rechargé
[ ] Glisser un Master .syx valide : overlay LOAD MASTER, chargement OK
[ ] Glisser un Master .m1km valide : overlay LOAD MASTER (ou dialogue
    .m1km) ; le chargement aboutit ou un message clair s'affiche
[ ] Glisser invalid-Master.syx ou invalid-Master.m1km : sur PATCH NAME,
    overlay « ******** » + « BAD FILE » (refus clair, pas de crash)
[ ] Glisser plusieurs Masters d'un coup : refus ou message clair, pas de
    crash

--------------------------------------------------------------------------------
13.4. Glisser-déposer — cas mixtes et refus
--------------------------------------------------------------------------------

Pendant un glisser-déposer invalide, l'afficheur PATCH NAME montre
« ******** » (huit astérisques) et « BAD FILE » (ou « BAD FILES » si
plusieurs éléments invalides). C'est le signal attendu de refus.

[ ] Glisser un patch .syx : titre temporaire LOAD PATCH ; le drop charge
    le patch (UNSAVED PATCH si besoin)
[ ] Glisser un patch .m1kp : même principe LOAD PATCH ; chargement OK
[ ] Glisser plusieurs patches ou un dossier : sélection acceptée ou
    message clair
[ ] Glisser invalid-PATCH.syx ou invalid-Patch.m1kp : sur PATCH NAME,
    overlay « ******** » + « BAD FILE » (pas de chargement, pas de crash)
[ ] Glisser un autre fichier non compatible : sur PATCH NAME, même
    overlay « ******** » + « BAD FILE » (ou « BAD FILES » si plusieurs),
    pas de crash

[ ] Résultat attendu : patches .syx / .m1kp et Masters .syx / .m1km
    gérés de façon prévisible ; rétrocompatibilité Matrix-1000 Editor
    utilisable ; pas d'écrasement surprise.

14. CRÉER DES VARIATIONS DE PATCH
================================================================================

Dans la section PATCH MANAGER, le module PATCH MUTATOR crée des variations
aléatoires contrôlées du patch courant — très pratique pour explorer de
nouveaux sons et textures rapidement.

Préparez : synthé détecté, patch chargé. Sauvegardez d'abord si le son de
départ vous est précieux (COMPUTER PATCHES → SAVE AS, ou section 13).

--------------------------------------------------------------------------------
14.1. Commutateurs, réglages et boutons
--------------------------------------------------------------------------------

Commutateurs de modules (choisir ce qui entre en jeu dans la mutation) :
- D1 = DCO 1
- D2 = DCO 2
- F/A = VCF/VCA
- F/T = FM / Track Generator
- R/P = Ramp / Portamento
- E1 / E2 / E3 = enveloppes 1, 2, 3
- L1 / L2 = LFO 1 et 2
- MM = MATRIX MODULATION

Réglages supplémentaires :
- AMOUNT : intensité de la variation
- RANDOM : degré d'aléatoire
- MODE : caractère de la mutation (ex. KINDRED, DRIFT, WARP, WILD)
- PITCH : traitement des hauteurs (ex. KEEP, CONSONANT, DISSONANT, FREE ;
  éventuellement une fenêtre d'octaves)

Boutons principaux :
- MUTATE : crée une nouvelle variation et l'envoie au synthé
- RETRY : autre tirage à partir du même point de départ
- HISTORY + < / > : parcourt les variations de la session
- C (Compare) : compare au patch de départ et verrouille le reste de
  l'édition tant qu'il est actif (bouton clignotant, GUI grisée)
- D (Delete) : supprime l'entrée sélectionnée dans l'historique
- F (Flush) : vide l'historique de la session
- E (Export) : exporte la session en fichiers .syx

--------------------------------------------------------------------------------
14.2. Mutation de base
--------------------------------------------------------------------------------

[ ] Au moins un commutateur (D1, D2, F/A, etc., MM) est activé
[ ] Réglez AMOUNT et RANDOM autrement que les défauts, puis MUTATE :
    variation audible / visible envoyée au synthé
[ ] RETRY propose une autre variante
[ ] HISTORY < / > parcourt la session de mutations
[ ] C (Compare) verrouille l'édition ; un message en bas de fenêtre le
    rappelle
[ ] Avec Compare actif : Undo/Redo patch et édition restent bloqués
[ ] Désactiver Compare restaure l'édition
[ ] D et F se comportent comme attendu (suppression / vidage de l'historique)
[ ] E exporte la session ; vous pouvez la rouvrir via le module
    COMPUTER PATCHES → OPEN
[ ] Les dialogues (historique plein, mutations non exportées, dossier déjà
    existant) proposent des choix clairs, sans perte silencieuse

--------------------------------------------------------------------------------
14.3. MODE et PITCH
--------------------------------------------------------------------------------

[ ] Changer MODE (ex. KINDRED puis WILD) : MUTATE donne un caractère
    différent — décrivez ce que vous entendez
[ ] Changer PITCH (KEEP vs FREE / CONSONANT, etc.) : la hauteur des
    variations est cohérente avec le choix

[ ] Résultat attendu : mutations audibles, Compare qui bloque bien, MODE/PITCH
    perceptibles, export rechargeable.

15. GÉRER LES BANQUES (MATRIX-1000 UNIQUEMENT)
================================================================================

Le Matrix-1000 organise ses patches en 10 banques de 100 patches, numérotées de
0 à 9. Dans la section PATCH MANAGER, le module BANK UTILITY sert à changer de
banque et à transférer des banques entières (COPY / PASTE / IMPORT / EXPORT).

Sur un Matrix-6/6R : ce module est entièrement grisé (pas de banques dans ces
deux modèles de synthé). C'est voulu.

--------------------------------------------------------------------------------
15.1. Sélection de banque
--------------------------------------------------------------------------------

[ ] Matrix-1000 : boutons 0 à 9 changent la banque ; le patch courant est
    relu depuis le synthé
[ ] Sur les banques 0 et 1, l'écriture d'un patch est possible (STORE, etc.)
[ ] Sur les banques 2 à 9, INIT / PASTE / STORE restent en lecture seule
    dans INTERNAL PATCHES (même règle qu'en section 10.5)
[ ] Changer de banque avec des modifications non sauvées suit la même
    logique UNSAVED PATCH qu'un changement de patch
[ ] Matrix-6/6R : BANK UTILITY est grisé

--------------------------------------------------------------------------------
15.2. COPY / PASTE / IMPORT
--------------------------------------------------------------------------------

Attention : ces actions peuvent écraser toute une banque. Sauvegardez
d'abord vos sons importants (EXPORT ci-dessous, ou fichiers .syx en
section 13). Travaillez de préférence sur les banques 0 ou 1.

[ ] IMPORT vers banque 0 ou 1 : une confirmation apparaît, puis une barre /
    fenêtre de progression, avec un résultat du type found / valid /
    imported (notez le texte)
[ ] IMPORT ou PASTE vers banque 2–9 est refusé ou grisé, avec un message
    clair
[ ] COPY banque A → PASTE banque B (toutes deux en RAM, ex. 0 → 1) : une
    confirmation et une progression s'affichent ; CANCEL restaure ou
    interrompt proprement
[ ] Pendant un transfert : l'UI reste cohérente (pas de clic accidentel qui
    casse tout) ; un message « in progress » ou un titre de progression est
    visible

--------------------------------------------------------------------------------
15.3. EXPORT de banque — arborescence attendue
--------------------------------------------------------------------------------

Quand vous lancez EXPORT, le Matrix-Control vous demande un dossier parent
(emplacement où vous souhaitez ranger l'export). Il crée ensuite un
sous-dossier nommé d'après la banque, puis y écrit les 100 fichiers .syx
(un par emplacement).

Exemple si vous exportez la banque 3 vers Documents/MatrixExports/ :

  Documents/MatrixExports/
    BANK 3/
      P00. NOMDUPATCH.syx
      P01. AUTRENOM.syx
      …
      P99. ….syx

Règles utiles :
- nom du sous-dossier : « BANK » + numéro (0 à 9), avec un espace
  (ex. BANK 0, BANK 3) ;
- chaque fichier : « P » + numéro sur 2 chiffres (P00…P99), puis « . »
  et le nom du patch nettoyé, extension .syx ;
- si le patch n'a pas de nom utilisable, le fichier peut s'appeler
  seulement P12.syx (sans segment de nom).

Si le sous-dossier BANK N existe déjà, un dialogue de confirmation peut
proposer d'écraser avant de recommencer l'export.

[ ] EXPORT de la banque sélectionnée : choisissez un dossier parent vide
    (ou un dossier de test) ; un sous-dossier « BANK N » est créé
[ ] Ce sous-dossier contient les 100 fichiers .syx nommés P00… à P99…
[ ] Ouvrez quelques fichiers au hasard via COMPUTER PATCHES → OPEN sur ce
    dossier : les patches se chargent ; les noms affichés sont cohérents
    avec les fichiers
[ ] Relancez EXPORT vers le même parent alors que « BANK N » existe déjà :
    le dialogue d'écrasement (s'il apparaît) est clair ; CANCEL n'écrase
    pas
[ ] Un message de succès s'affiche en bas de fenêtre en fin d'export
    réussi

[ ] Résultat attendu : changement de banque fiable ; transferts contrôlés
    sur RAM ; banques d'usine protégées ; arborescence EXPORT conforme ;
    zone grisée sur un Matrix-6/6R.

16. RÉGLAGES GLOBAUX DU SYNTHÉ (MATRIX-1000 UNIQUEMENT)
================================================================================

La section MASTER EDIT regroupe des réglages globaux au synthétiseur (canal
MIDI, vibrato global, accordage, etc.).

Modules : MIDI, VIBRATO, MISC.

Sur un Matrix-6/6R, toute cette colonne est grisée — c'est voulu. La gestion du
Master sur ces modèles est très différente de celle du Matrix-1000, et le
Matrix-Control ne l'édite pas encore. Une version ultérieure pourra
éventuellement en proposer le support ; pour cette bêta, considérez MASTER
EDIT comme réservé au Matrix-1000.

--------------------------------------------------------------------------------
16.1. Éditer la section MASTER EDIT
--------------------------------------------------------------------------------

[ ] Matrix-1000 : les modules MIDI, VIBRATO et MISC sont visibles et éditables
[ ] Changez le CHANNEL MIDI avec prudence : comportement cohérent
[ ] Bouton I sur un module : dialogue RESET MASTER MODULE? RESET / CANCEL
    fonctionnent
[ ] Un réglage master influence le comportement général, quel que soit le
    patch chargé
[ ] Matrix-6/6R : MASTER EDIT est grisé

--------------------------------------------------------------------------------
16.2. UNISON DETUNE (selon EPROM)
--------------------------------------------------------------------------------

Dans MASTER EDIT → module MISC, le réglage UNISON DETUNE n'est actif
qu'avec une EPROM « optimisée » (GLIGLI, TAUNTEK ou UNTERGEEK dans
SETTINGS → EPROM TYPE). Avec une EPROM d'usine (FACTORY) ou UNKNOWN, le
contrôle est grisé ; un message en bas de fenêtre peut rappeler qu'il
faut une EPROM optimisée.

Ce n'est pas le DETUNE du module DCO 2 (patch) : ici, c'est le désaccord
global Unison côté Master (pilotable via le Contrôleur Continu MIDI #94).

[ ] Notez l'EPROM TYPE affiché (section 7.4 / SETTINGS)
[ ] EPROM GLIGLI, TAUNTEK ou UNTERGEEK : UNISON DETUNE est éditable ;
    bougez-le — comportement cohérent (son / affichage) ; notez ce que
    vous entendez avec Unison actif
[ ] EPROM FACTORY ou UNKNOWN : UNISON DETUNE est grisé ; un message
    d'aide / footer peut l'expliquer — ce n'est pas un bug
[ ] Matrix-6/6R : indiquez [-] (MASTER EDIT est grisé)

--------------------------------------------------------------------------------
16.3. Utilitaires Master (INIT)
--------------------------------------------------------------------------------

Le chargement, l'enregistrement et le glisser-déposer des fichiers Master
(.syx, .m1km) sont traités dans la section 13.3. Ici, on ne teste que les
utilitaires liés aux réglages globaux.

INIT global remet les réglages Master du synthé à un état de départ. Vous
le lancez depuis SETTINGS (zone MASTER / UTILITY). Une confirmation doit
apparaître avant d'appliquer — c'est volontaire, car l'action touche toute
la machine, pas seulement le patch affiché.

INIT TEMPLATE (Master) permet d'enregistrer votre propre modèle de Master
(SAVE AS INIT), puis de le supprimer (DELETE) si besoin. Ce modèle sert de
référence pour les initialisations Master — distinct du modèle de patch
(INIT TEMPLATE patch, section 17).

[ ] INIT global (SETTINGS → MASTER / UTILITY) : une confirmation est
    demandée avant de réinitialiser ; après confirmation, le comportement
    est cohérent (pas de plantage)
[ ] (Optionnel) INIT TEMPLATE Master : SAVE AS INIT enregistre un modèle ;
    DELETE le retire ; les libellés / dialogues restent clairs

--------------------------------------------------------------------------------
16.4. MEMORY PROTECT et BANK LOCK
--------------------------------------------------------------------------------

Dans le module MISC de MASTER EDIT (Matrix-1000), deux interrupteurs
protègent la mémoire :

- MEMORY PROTECT : empêche d'écrire des patches dans la mémoire du synthé
  (STORE peut sembler « cassé » s'il est actif) ;
- BANK LOCK : verrouille le changement de banque.

Travaillez sur une banque réinscriptible (0 ou 1). Notez l'état de départ
avant de basculer ces options, puis remettez-les comme vous les voulez en
fin de test.

[ ] MEMORY PROTECT activé : tentez STORE — l'écriture est bloquée ou un
    message clair l'indique ; désactivez, STORE redevient possible
[ ] BANK LOCK activé : le changement de banque est bloqué ou clairement
    signalé ; désactivez, les boutons 0–9 de BANK UTILITY réagissent à
    nouveau
[ ] Remettez MEMORY PROTECT / BANK LOCK dans l'état souhaité pour la suite

[ ] Résultat attendu : édition Master possible sur un Matrix-1000 seulement ;
    UNISON DETUNE conforme à l'EPROM ; INIT et protections mémoire
    compréhensibles, sans crash.

17. RÉGLAGES DU MATRIX-CONTROL
================================================================================

Ces réglages, accessibles via un clic sur le logo MATRIX-CONTROL →
SETTINGS… (ou raccourci Cmd+, sous macOS / Ctrl+, sous Windows et Linux),
s'ouvrent dans la fenêtre SETTINGS et modifient le comportement au
quotidien. Le menu du logo propose aussi SKIN, UI SCALE et ABOUT…

--------------------------------------------------------------------------------
17.1. Apparence : SKIN et UI SCALE
--------------------------------------------------------------------------------

Vous pouvez changer l'apparence hors de GETTING STARTED :

- menu logo → SKIN / UI SCALE ;
- ou listes SKIN / UI SCALE dans SETTINGS → USER INTERFACE.

Raccourcis utiles (fenêtre Matrix-Control au premier plan) :
- Cmd/Ctrl + / − : augmenter / diminuer UI SCALE ;
- Cmd/Ctrl + 0 : UI SCALE à 100 % ;
- double-clic sur le logo MATRIX-CONTROL : revient aussi à 100 % ;
- Cmd/Ctrl + 1…6 : skins de base (ordre du menu ; les chiffres
  s'affichent aussi en hint dans le menu logo) ;
- Cmd/Ctrl + flèches : parcourir les skins par familles ;
- Cmd/Ctrl+Shift+flèches : parcours élargi à tous les skins.

[ ] Changez SKIN via le menu logo : l'interface se met à jour
[ ] Changez UI SCALE (menu ou SETTINGS) : la fenêtre se redimensionne
    sans plantage
[ ] Double-clic sur le logo : UI SCALE revient à 100 %
[ ] Cmd/Ctrl+0 : même retour à 100 %
[ ] Cmd/Ctrl+1 (ou un autre chiffre proposé dans le menu) : le skin
    correspondant s'applique
[ ] Les raccourcis fléchés (avec et sans Shift) changent de skin de façon
    prévisible — notez si un raccourci ne répond pas sur votre clavier
    (ex. disposition AZERTY)

--------------------------------------------------------------------------------
17.2. Avertissements, aide et modèles de patch
--------------------------------------------------------------------------------

[ ] UNSAVED STATE : ALWAYS WARN vs NEVER WARN — le dialogue UNSAVED
    PATCH apparaît ou non comme attendu
[ ] CONTEXTUAL HELP sur SHOW : le survol d'un contrôle affiche le texte
    HELP en bas de fenêtre ; sur HIDE, ce texte ne s'affiche plus
[ ] INIT TEMPLATE (PATCH) dans SETTINGS : SAVE AS INIT enregistre un
    modèle ; ensuite, INIT dans INTERNAL PATCHES utilise ce modèle
    (PATCH NAME « * INIT * » ou équivalent selon le modèle)

--------------------------------------------------------------------------------
17.3. Noms affichés (Matrix-1000 uniquement)
--------------------------------------------------------------------------------

Dans SETTINGS, la liste MATRIX-1000 PATCHES choisit comment afficher le
nom d'un patch chargé depuis la mémoire du synthé :

- DISPLAY MUSICAL NAMES (défaut) : privilégie un nom « musical » /
  d'usine quand il est disponible (surtout utile sur les banques ROM) ;
- DISPLAY HARDWARE NAMES : montre le nom tel qu'il est côté machine, ou
  une étiquette de type B0-P05 s'il n'y a pas de nom utilisable.

[ ] Matrix-1000 : basculez DISPLAY MUSICAL NAMES ↔ DISPLAY HARDWARE
    NAMES ; chargez un patch en banque d'usine puis en banque RAM — le
    PATCH NAME (ou le libellé associé) change de façon cohérente avec
    l'option ; notez ce que vous voyez
[ ] Matrix-6/6R : indiquez [-] (cette liste ne s'applique pas)

--------------------------------------------------------------------------------
17.4. HARDWARE LATENCY (plugin uniquement)
--------------------------------------------------------------------------------

HARDWARE LATENCY (onglet MIDI & DEVICE) indique au DAW un délai en
millisecondes pour mieux aligner l'audio du synthé (qui traverse votre
interface audio) avec le reste du projet. Ça ne change pas le son du Matrix
lui-même : cela informe l'hôte pour lui permettre de gérer la compensation de
latence. Réglez seulement si vous remarquez un décalage MIDI/audio dans le DAW.

[ ] Plugin seulement : HARDWARE LATENCY est visible et réglable ; une
    petite variation de la valeur ne fait pas planter le plugin ni le DAW
[ ] Standalone : HARDWARE LATENCY n'apparaît pas — c'est normal
    (indiquez [-] si vous ne testez que le Standalone)

--------------------------------------------------------------------------------
17.5. ABOUT et fermeture
--------------------------------------------------------------------------------

[ ] Logo → ABOUT… : la version du Matrix-Control est lisible
[ ] Échap ferme ABOUT et/ou SETTINGS sans plantage

[ ] Résultat attendu : SKIN / UI SCALE / raccourcis utilisables ; options
    SETTINGS fidèles à leur libellé ; pas de plantage en ouvrant/fermant
    SETTINGS.
