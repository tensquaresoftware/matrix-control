1. PRÉREQUIS
================================================================================

1.1. Matériel
-------------
[ ] Synthétiseur Oberheim Matrix-1000 (minimum pour le smoke complet)
[ ] Optionnel : Matrix-6 ou Matrix-6R (pour vérifier les zones grisées)
[ ] Interface MIDI (USB-MIDI ou interface audio avec MIDI) — DEUX sens :
    ordinateur → synthé ET synthé → ordinateur
[ ] Câblage audio du synthé vers l'interface / la table (Matrix-Control
    ne génère pas le son)

1.2. Ordinateur / OS à couvrir
------------------------------
[ ] macOS Apple Silicon (ARM)
[ ] macOS Intel (si disponible)
[ ] Windows 11
[ ] Windows 10
[ ] Linux Ubuntu 24.x
[ ] Linux Ubuntu 26.x (si disponible)

1.3. Logiciels
--------------
[ ] DAW au choix (Ableton Live, Logic Pro, Cubase, Reaper, Reason, etc.)
[ ] Build / tag Matrix-Control à tester (ZIP, pas d'installateur)
[ ] Éditeur de texte de base pour cocher ce fichier

1.4. À savoir avant de commencer
--------------------------------
- Pas d'installateur : ZIP + copies manuelles.
- Builds NON notarisés (macOS) et NON signés Authenticode (Windows) :
  les avertissements Gatekeeper / SmartScreen sont NORMAUX, pas des bugs.
- ASIO (Windows Standalone) : peut être absent de la première bêta publique.
  Tester l'audio Standalone AVEC et SANS ASIO (WASAPI / drivers système).
  Ne pas considérer l'absence d'ASIO comme un échec si le build est sans ASIO.
- Sauvegarde : avant STORE, MUTATE intensif, ou import de banque, sauvegardez
  les patches RAM importants (COMPUTER PATCHES → SAVE AS, ou export banque).
- Sur Matrix-1000, si STORE / édition semble sans effet : vérifier MEMORY
  PROTECT / BANK LOCK sur la machine (ou dans MASTER EDIT) avant de signaler
  un bug.

3. INSTALLATION ET PREMIER LANCEMENT
================================================================================

Pas d'installateur. Extraire le ZIP, copier à la main, rescanner le DAW.

3.1. Contenu attendu du ZIP (selon plateforme)
----------------------------------------------
[ ] Standalone présent
[ ] VST3 présent
[ ] AU présent (macOS seulement — sinon écrire N/A)
[ ] Documentation présente (manuel et/ou ce guide)
[ ] Skin Designer ABSENT du ZIP grand public (normal)

Si échec : noter le nom exact de l'archive et ce qui manque.


--------------------------------------------------------------------------------
3.2. macOS (ARM et Intel) — même procédure
--------------------------------------------------------------------------------

Chemins cibles :
  AU     → ~/Library/Audio/Plug-Ins/Components/
  VST3   → ~/Library/Audio/Plug-Ins/VST3/
  App    → /Applications/  (ou laisser à côté du ZIP)

Étapes :
[ ] Extraire le ZIP
[ ] Copier Matrix-Control.component vers le dossier Components
[ ] Copier Matrix-Control.vst3 vers le dossier VST3
[ ] (Optionnel) Copier Matrix-Control.app vers /Applications
[ ] Lever la quarantaine après téléchargement navigateur / GitHub :
      xattr -cr /chemin/vers/Matrix-Control.app \
                /chemin/vers/Matrix-Control.vst3 \
                /chemin/vers/Matrix-Control.component
    (Adapter les chemins à vos copies.)
[ ] Premier lancement : si macOS dit « développeur non identifié »,
    clic droit → Ouvrir, ou autoriser dans Réglages Système.
    Ceci est ATTENDU (build non notarié). Ce n'est PAS un bug.
[ ] Lancer le Standalone : la fenêtre s'ouvre
[ ] Dans le DAW : rescan plugins si besoin ; Matrix-Control apparaît en AU et/ou VST3
[ ] Charger le plugin sur une piste instrument / MIDI

Résultat attendu : app et plugins démarrent. Après xattr, pas de message
« endommagé » / « damaged ». Un avertissement « développeur non identifié »
reste NORMAL (build non notarié) — clic droit → Ouvrir. Vous n'avez pas à
relancer codesign vous-même : la CI signe déjà en ad-hoc.

Si échec, noter : message exact Gatekeeper, chemin copié, commande xattr,
Intel vs ARM, version macOS.


--------------------------------------------------------------------------------
3.3. Windows 10 / 11
--------------------------------------------------------------------------------

Chemins cibles :
  VST3 → C:\Program Files\Common Files\VST3\
  Standalone → Matrix-Control.exe (depuis le ZIP, ou dossier de votre choix)

Étapes :
[ ] Extraire le ZIP
[ ] Copier Matrix-Control.vst3 vers le dossier VST3 système
    (peut demander des droits administrateur). Sans admin : copier vers un
    dossier VST3 utilisateur / chemin custom de votre DAW, puis indiquer
    ce chemin au DAW et rescanner.
[ ] Lancer Matrix-Control.exe
[ ] Si SmartScreen / « Windows a protégé votre PC » apparaît :
    informations complémentaires → exécuter quand même.
    Ceci peut être NORMAL (pas de signature Authenticode). Ce n'est PAS un bug.
[ ] Dans le DAW : rescan VST3 ; charger Matrix-Control
[ ] Vérifier qu'un seul logiciel à la fois occupe le port MIDI
    (sous Windows, un port est souvent exclusif)

Résultat attendu : Standalone et VST3 démarrent ; plugin visible après rescan.

Si échec, noter : message SmartScreen exact, chemin VST3, DAW, Win10 vs Win11.


--------------------------------------------------------------------------------
3.4. Linux (Ubuntu 24 / 26)
--------------------------------------------------------------------------------

Chemins cibles :
  VST3 → ~/.vst3/
  Standalone → binaire Matrix-Control du ZIP

Étapes :
[ ] Extraire le ZIP
[ ] Copier Matrix-Control.vst3 vers ~/.vst3/
[ ] Rendre le Standalone exécutable si besoin (chmod +x)
[ ] Lancer le Standalone depuis un terminal si utile (voir messages d'erreur)
[ ] Dans le DAW : rescan VST3 ; charger Matrix-Control
[ ] Audio Standalone : drivers système / JACK selon le build — noter ce qui
    apparaît dans SETTINGS → AUDIO

Résultat attendu : Standalone et VST3 démarrent ; pas de dépendance manquante
bloquante au lancement.

Si échec, noter : message terminal, distro exacte, présence/absence de JACK.


================================================================================
4. GETTING STARTED
================================================================================

Précondition : premier lancement (ou SETTINGS → GETTING STARTED →
RUN SETUP AGAIN / SETUP WIZARD sur SHOW WHEN INCOMPLETE).

4.1. Introduction
-----------------
[ ] La fenêtre GETTING STARTED s'ouvre (auto ou via RUN SETUP AGAIN)
[ ] CONTINUE avance ; CONFIGURE LATER ferme sans tout marquer terminé

4.2. Étapes communes (plugin et Standalone)
-------------------------------------------
[ ] STEP 1 USER INTERFACE : changer UI SCALE et SKIN — l'UI réagit
[ ] STEP 2 SYNTH COMMUNICATION : choisir SYNTH FROM / SYNTH TO,
    voir le badge DEVICE, choisir ou confirmer EPROM TYPE
[ ] STEP 3 MIDI KEYBOARD :
    - Plugin : pas de liste KEYBOARD FROM (HOST) ; FINISH après cette étape
    - Standalone : liste KEYBOARD FROM ; SKIP possible ; puis étape Audio

4.3. Standalone seulement — STEP 4 AUDIO
----------------------------------------
[ ] Choisir une interface audio système (WASAPI / Core Audio / ALSA / etc.)
[ ] Choisir les canaux d'écoute SYNTH FROM (AUDIO — distinct du port MIDI)
[ ] FINISH ferme l'assistant

Résultat attendu : vous pouvez terminer même si le MIDI n'est pas encore
parfait ; les étapes marquées terminées ne forcent pas la détection.

Si échec, noter : format (plugin/Standalone), étape bloquée, message en bas
de fenêtre, comportement CONFIGURE LATER / rappel au relancement.


================================================================================
5. DÉTECTION / DIALOGUE MIDI
================================================================================

Précondition : câblage bidirectionnel + synthé allumé.

5.1. Sélection des ports
------------------------
[ ] Régler SYNTH FROM / SYNTH TO (bandeau FROM SYNTH / TO SYNTH, ou
    SETTINGS → MIDI & DEVICE, ou GETTING STARTED étape 2)
[ ] Les voyants MIDI clignotent quand du trafic circule
[ ] Le badge DEVICE (bas droite) affiche Matrix-1000, Matrix-6, ou équivalent
    (un Matrix-6R peut apparaître comme Matrix-6 — noter si c'est le cas)
[ ] Si NOT CONNECTED : suivre le message footer (câbles, ports, power-cycle)

5.2. Contrôles verrouillés sans détection
-----------------------------------------
[ ] Sans détection correcte, l'édition reste verrouillée (comportement voulu)
[ ] Avec détection, PATCH EDIT et zones utiles se débloquent

5.3. Windows — port déjà utilisé
--------------------------------
[ ] Si le port ne s'ouvre pas : fermer l'autre app / DAW qui l'occupe,
    ou utiliser un port MIDI virtuel ; réessayer

Résultat attendu : DEVICE reconnu ; édition possible ; pas de spam d'erreurs
si les ports sont corrects.

Si échec, noter : OS, ports choisis, message footer exact, autre app MIDI
ouverte, type de machine physique vs badge.


================================================================================
6. PATCH EDIT (parcours représentatif)
================================================================================

Précondition : synthé détecté + un patch chargé (INTERNAL PATCHES).

6.1. Édition live
-----------------
[ ] Modifier un paramètre DCO 1 (ex. forme d'onde / detune) — le son change
[ ] Modifier VCF (cutoff / résonance) — le son change
[ ] Déplacer un point sur une enveloppe (ENV) à la souris
[ ] Déplacer un point du Track Generator (FM/TRACK) à la souris

6.2. I / C / P sur un module
----------------------------
[ ] I (Init) remet le module à des valeurs par défaut
[ ] C (Copy) puis P (Paste) sur un module compatible fonctionne
[ ] P grisé sur module incompatible + message footer si on clique

6.3. UNDO / REDO
----------------
[ ] Annuler (Cmd+Z / Ctrl+Z) revient en arrière sur la dernière édition
[ ] Rétablir (Cmd+Shift+Z / Ctrl+Shift+Z) restaure
[ ] Charger un autre patch efface l'historique d'annulation (nouvelle baseline)

6.4. PATCH NAME
---------------
[ ] L'afficheur PATCH NAME (8 caractères) est en lecture seule
[ ] Il se met à jour au chargement d'un patch / mutation

Résultat attendu : édition temps réel audible ; undo cohérent ; pas de crash.

Si échec, noter : module, paramètre, machine, EPROM, Standalone vs plugin.


================================================================================
7. MATRICE DE MODULATION (MATRIX MODULATION)
================================================================================

Précondition : synthé détecté, patch chargé.

[ ] Sur un bus (0–9) : choisir SOURCE, AMOUNT, DESTINATION ≠ NONE
[ ] Jouer une note : la modulation est audible / visible sur le paramètre
[ ] I sur un bus réinitialise ce bus
[ ] Réordonner deux bus par glisser-déposer sur le numéro # (départ gris,
    arrivée rouge) — les contenus s'échangent, les numéros restent 0–9
[ ] UNDO après réordonnancement revient en arrière (une étape)

Résultat attendu : bus éditables ; reorder stable ; pas de bus « fantôme ».

Si échec, noter : numéro de bus, SOURCE/DEST, ordre après drop.


================================================================================
8. INTERNAL PATCHES ET COMPUTER PATCHES
================================================================================

8.1. INTERNAL PATCHES (mémoire du synthé)
-----------------------------------------
[ ] < / > change de patch ; le patch est relu depuis le synthé
[ ] Double-clic numéro de patch : saisie directe 0–99
[ ] STORE écrit le patch dans l'emplacement courant (banques RAM seulement)
[ ] Sur Matrix-1000 banques 2–9 (ROM) : INIT / PASTE / STORE grisés
[ ] Dialogue Unsaved patch si modifications non STORE/SAVE : Cancel / Discard /
    Store / Save selon contexte

8.2. COMPUTER PATCHES (fichiers .syx)
-------------------------------------
[ ] OPEN : choisir un dossier de patches
[ ] SAVE AS : créer un .syx ; SAVE : écraser le fichier associé
[ ] Charger un .syx depuis la liste < / >
[ ] Si Patch name mismatch : Internal / Filename / Cancel se comportent
    comme attendu

Résultat attendu : navigation patch OK ; STORE sur RAM OK ; fichiers .syx
lisibles ; pas d'écrasement surprise hors action explicite.

Si échec, noter : banque/patch, message dialog, chemin dossier.


================================================================================
9. BANK UTILITY (Matrix-1000)
================================================================================

Précondition : Matrix-1000 détecté.
Sur Matrix-6/6R : toute la zone doit être GRISEE.

[ ] Matrix-6/6R seulement : BANK UTILITY entièrement grisé (N/A sur 1000)
[ ] Boutons banque 0–9 changent la banque ; le patch courant est relu
[ ] Banques 0–1 : écriture possible (STORE etc. selon contexte)
[ ] Banques 2–9 : lecture seule pour INIT / PASTE / STORE dans INTERNAL PATCHES
[ ] (Si proposé dans votre build) import / export de banque : tester une fois
    avec prudence — sauvegarde RAM / export préalable recommandée

Résultat attendu : changement de banque fiable ; ROM protégée ; 6/6R grisé.

Si échec, noter : banque, patch, état des boutons, type de machine.


================================================================================
10. MASTER EDIT (Matrix-1000)
================================================================================

Précondition : Matrix-1000 détecté.
Sur Matrix-6/6R : colonne MASTER EDIT GRISEE.

[ ] Matrix-6/6R seulement : MASTER EDIT entièrement grisé (N/A sur 1000)
[ ] Modules MIDI / VIBRATO / MISC visibles et éditables sur 1000
[ ] Changer CHANNEL MIDI (avec prudence) — synthé suit / reste cohérent
[ ] Bouton I sur un module master : dialogue RESET MASTER MODULE?
    Reset / Cancel fonctionnent
[ ] Les réglages master s'appliquent globalement (pas à un seul patch)

Résultat attendu : master éditable sur 1000 seulement ; confirmations OK.

Si échec, noter : module, paramètre, message, machine.


================================================================================
11. PATCH MUTATOR
================================================================================

Précondition : synthé détecté, patch chargé.

[ ] Au moins un commutateur module (D1, D2, F/A, …, MM) actif
[ ] Régler AMOUNT et RANDOM à des valeurs distinctes (pas seulement les défauts)
    puis MUTATE — la variation est audible / visible
[ ] MUTATE crée une variation et l'envoie au synthé
[ ] RETRY tire une autre variante depuis le même point de départ
[ ] HISTORY < / > parcourt les variations de session
[ ] C (Compare) compare au départ et VERROUILLE le reste de l'édition
    tant qu'il est actif (message footer)
[ ] Désactiver Compare restaure l'édition
[ ] E exporte la session (.syx) ; rouvrir via COMPUTER PATCHES → OPEN
[ ] Dialogues Unsaved mutations / history full / export folder exists :
    choix clairs, pas de perte silencieuse

Résultat attendu : mutations audibles ; Compare bloque bien ; export rechargeable.

Si échec, noter : AMOUNT/RANDOM, modules activés, dialogue, crash éventuel.


================================================================================
12. STANDALONE VS PLUGIN
================================================================================

12.1. Plugin (AU / VST3 selon OS)
--------------------------------
[ ] Charge dans le DAW sans crash
[ ] MIDI clavier via la piste hôte (KEYBOARD FROM = HOST)
[ ] Audio du synthé sur une piste audio séparée (pas généré par le plugin)
[ ] GETTING STARTED sans étape Audio
[ ] SETTINGS accessibles (logo MATRIX-CONTROL ou raccourci)

12.2. Standalone
----------------
[ ] Fenêtre autonome ; SETTINGS → AUDIO disponible
[ ] Écoute du retour synthé via l'interface choisie
[ ] KEYBOARD FROM sélectionnable (ou SKIP dans Getting Started)
[ ] INPUT GAIN / monitoring bandeau si présent : réactif

12.3. Audio Standalone Windows — avec et sans ASIO
--------------------------------------------------
[ ] Sans ASIO : WASAPI (ou driver système) — entrée audible, latence acceptable
[ ] Avec ASIO (SEULEMENT si le build l'expose) : périphérique ASIO listable,
    sélectionnable, audio OK
[ ] Si ASIO absent du build : NOTER « build sans ASIO » — ce n'est PAS un bug
    de la première bêta publique tant que la licence Steinberg n'est pas close

Résultat attendu : plugin et Standalone utilisables ; audio Standalone OK
au moins via drivers système.

Si échec, noter : format, DAW, driver audio, présence/absence ASIO, sample rate.


================================================================================
13. ABLETON LIVE — AUTO-SCALE (Windows)
================================================================================

Précondition : Windows + Ableton Live + VST3 Matrix-Control.

Problème connu : si « Auto-Scale Plugin Window » est ACTIVÉ (souvent par
défaut), l'UI VST3 est FLOUE à toutes les UI Scale. Le Standalone reste net.

[ ] Dans le Browser Live : clic droit sur l'icône du plug-in Matrix-Control
    (pas seulement la barre de titre du device)
[ ] Désactiver Auto-Scale Plugin Window
[ ] Recharger le device
[ ] Vérifier que l'UI VST3 est nette
[ ] Comparer avec le Standalone sur la même machine (doit rester net)

Résultat attendu : VST3 net après désactivation ; documenter si le chemin
menu Live diffère selon la version.

Si échec, noter : version Live, chemin exact du menu, capture si possible.


================================================================================
14. LIMITATIONS CONNUES À VÉRIFIER / NOTER
================================================================================

Ces points ne sont pas forcément des bugs à « corriger pour la bêta » —
confirmez le comportement et notez tout écart.

[ ] Unison (Matrix-1000) : dans RAMP/PORTAMENTO (et réglages Unison liés),
    activer / régler Unison. Comportement parfois contre-intuitif
    (UI vs ce que l'on croit commander). Décrire ce que vous voyez et entendez.
[ ] Keyboard Mode : dans RAMP/PORTAMENTO, changer le mode clavier.
    Bug firmware connu ; contourné / résolu avec EPROM Untergeek v1.21.
    Noter votre EPROM et tout comportement étrange (notes collées, mode
    qui ne colle pas, etc.).
[ ] MEMORY PROTECT / BANK LOCK : si actifs, STORE peut sembler « cassé »
    — vérifier avant de reporter.
[ ] MASTER EDIT et BANK UTILITY grisés sur Matrix-6/6R (voulu)
[ ] Builds non notarisés / non Authenticode : avertissements OS normaux
[ ] Matrix-6R peut s'afficher comme Matrix-6
[ ] ASIO peut manquer selon le build — tester WASAPI / drivers système
[ ] Skin Designer non inclus dans le ZIP grand public
