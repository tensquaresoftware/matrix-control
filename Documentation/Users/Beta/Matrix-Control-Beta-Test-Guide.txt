WELCOME
--------------------------------------------------------------------------------

Thank you for taking part in the Matrix-Control beta tests! :)

Matrix-Control is a modern MIDI editor for the Oberheim Matrix-1000,
Matrix-6 and Matrix-6R synthesizers. Used as a standalone application or as
a VST3/AU plugin, it acts as an on-screen "remote control": it sends and
receives MIDI messages (settings, patches, master) so you can view and edit
the synth more comfortably. It does not produce sound and does not record
audio either — the audio always comes from the synthesizer. To hear it, you
must route the synth audio output to an input on your audio interface, mixer
or speakers.

--------------------------------------------------------------------------------
WHAT IS THIS GUIDE FOR?
--------------------------------------------------------------------------------

This document is not a course on sound synthesis, nor the full Matrix-Control
user manual. It is a TEST guide: a list of concrete situations to try on your
setup, to check that the beta software behaves correctly before a final,
stable release. Your feedback (especially bugs and moments of confusion) is
extremely valuable!

How to use this guide
---------------------
Work through it in order. After the preparation phase (sections 1 to 3),
each section sets the context, asks you to test, then asks you to fill in
the checkboxes as you go.

1. Open the guide in a basic text editor (TextEdit on macOS, Notepad on
   Windows, gedit on Linux, etc.) and fill it in on screen. Avoid printing
   it: checkboxes and notes are much easier to send back by email as a
   text file.

2. Replace the character between the brackets according to the result
   (uppercase or lowercase accepted):
     [ ]  point not yet covered
     [V]  success (test = Valid)
     [F]  failure (test = Failure)
     [?]  unsure — tested, but the result is unclear or ambiguous
     [-]  not applicable to your setup
          (e.g. AU plugin on Windows, BANK UTILITY on a Matrix-6/6R)

   For [F] or [?], add detail under "Personal notes" (just below the
   relevant section): exact on-screen message, what you expected, what
   happened. That is the place for detail.

3. You may not finish every test: that is fine. PART A (essential tests)
   matters most. If you stop at the end of PART A and move on to the
   summary (section 19) then sending results (section 20), your feedback
   is already very useful! ;)

Two paces in the same guide
---------------------------
- PART A — Essential tests: sections 4 to 12 (about 30 to 45 minutes).
  You may stop afterwards → PART C (summary + send).
- PART B — In-depth tests: sections 13 to 17 (optional continuation for
  a full path). With A + B, you have completed a full path.
- PART C — End of session: known points, summary, sending results.

A single computer + DAW + Oberheim synth + Matrix-Control combination is

About on-screen names
---------------------
The Matrix-Control user interface (GUI) is in English. Screen and button
names in this guide match what you see on screen: GETTING STARTED,
PATCH EDIT, BANK UTILITY, and so on.

Quick layout of the main window
-------------------------------
Once the software is open, the user interface (GUI) is organized roughly
like this:

+--------------------------------------------------------------------+
| Logo MATRIX-CONTROL | Undo/Redo, MIDI LEDs (FROM/TO SYNTH, etc.)   | <- HEADER
+--------------------------------------------------------------------+
|                     |                        |                     |
| PATCH EDIT          | MATRIX MODULATION      | MASTER EDIT         |
| - 10 sound modules: | (10 modulation buses)  | (Matrix-1000        |
|   DCO, VCF, ENV…    |------------------------|  only; grayed out   |
| - 5 displays:       | PATCH MANAGER          |  on Matrix-6/6R)    | <- BODY
|   - 3 Envelopes     | - INTERNAL PATCHES     |                     |
|   - 1 Track Gen.    | - COMPUTER PATCHES     |                     |
|   - 1 PATCH NAME    | - BANK UTILITY         |                     |
|                     | - PATCH MUTATOR        |                     |
+--------------------------------------------------------------------+
| User messages / help                     DEVICE badge (synth type) | <- FOOTER
+--------------------------------------------------------------------+

Useful vocabulary (aligned with the user manual):
- Window = the main Matrix-Control window, or a window that opens on top
  (SETTINGS, ABOUT)
- Panel = large regions of the main window (HEADER, BODY, FOOTER)
- Section = large block inside the BODY panel (PATCH EDIT, MATRIX
  MODULATION, PATCH MANAGER, MASTER EDIT)
- Module = block inside a section (DCO 1, DCO 2, INTERNAL PATCHES,
  PATCH MUTATOR, MIDI, VIBRATO, MISC, BANK UTILITY, etc.)
- Group = sub-part of a module (BROWSER, MEMORY, STORAGE, etc.)
- Modulation bus = one of the ten rows in the MATRIX MODULATION section
- Dialog = small confirmation/choice box (UNSAVED PATCH,
  RESET MASTER MODULE?, PATCH MUTATOR alerts, etc.)

A more detailed user manual will ship with Matrix-Control in due course;
this test guide does not replace it.

2. IMPORTANT POINTS BEFORE YOU START
================================================================================

These points help you avoid mistaking intended behavior or common
macOS / Windows messages for bugs.

--------------------------------------------------------------------------------
2.1. ZIP distribution
--------------------------------------------------------------------------------
In its beta version, Matrix-Control ships as a ZIP archive, with no
installer wizard. You extract the ZIP, then copy the application and/or
plugins yourself to the usual locations on your system (detail in
section 4). There is therefore no classic "Run > Next > Next > ... >
Finish" wizard yet: that is not an oversight.

--------------------------------------------------------------------------------
2.2. macOS or Windows security messages
--------------------------------------------------------------------------------
Beta executables do not yet go through Apple's paid certification
("notarization") or Microsoft Windows publisher signing.

Frequent and NORMAL outcomes:
- on macOS: a warning such as "unidentified developer";
- on Windows: a SmartScreen screen such as "Windows protected your PC".

This is generally NOT a virus and NOT a plugin bug. Section 4 explains
how to continue safely (for example right-click → Open on macOS).

--------------------------------------------------------------------------------
2.3. Audio monitoring in the Standalone app under Windows (ASIO)
--------------------------------------------------------------------------------
In Standalone mode (standalone application, outside a DAW), Matrix-Control
can monitor the synth's audio return via the audio interface connected to
your computer. Under Windows, that often uses the system audio driver
(sometimes called WASAPI).

In time, Matrix-Control should also offer ASIO: a driver widely used in
music production, usually more responsive (lower latency). For now, ASIO
may still be missing from early beta builds: the developer is waiting for
a licence agreement with Steinberg, the owner of that technology. If you
do not see ASIO in the audio list, that is not a bug: note it, and mainly
check that monitoring works with the system driver. The essential point
is to hear the synth and be able to edit it.

--------------------------------------------------------------------------------
2.4. Protect your internal patches before starting the tests
--------------------------------------------------------------------------------
Some steps write to the synth memory (STORE, PATCH MUTATOR variations,
bank transfers). If you care about patches already in your
Matrix-1000/6/6R, save them to the computer first, once Matrix-Control is
installed (section 4) and the synth is detected (section 7).

Method used in this guide: COMPUTER PATCHES module (PATCH MANAGER
section) → SAVE AS button → .syx files (one file per patch). A concrete
reminder sits just before write tests (section 12). The full file path
(including folders provided in the ZIP) is in section 13.

--------------------------------------------------------------------------------
2.5. If STORE seems not to save
--------------------------------------------------------------------------------
On a Matrix-1000, memory protect or bank lock (MEMORY PROTECT / BANK LOCK,
on the machine or in the MASTER EDIT section) can block patch writes.

On a Matrix-6/6R, check especially the Memory Protect switch on the back
of the machine (set to Off to allow saving), and possibly the per-patch
protect on the front panel. Those settings are not editable in
Matrix-Control (MASTER EDIT is grayed out).

Check this before concluding it is a bug.

4.2. Testing on macOS
--------------------------------------------------------------------------------

This section covers macOS on Apple Silicon or Intel.

4.2.1. Copy the files
---------------------
Where to copy (~ means your home folder, e.g. /Users/YourName):

  AU plugin   →  ~/Library/Audio/Plug-Ins/Components/
  VST3 plugin →  ~/Library/Audio/Plug-Ins/VST3/
  Application →  /Applications/
                 (or next to the ZIP, if you prefer)

In Finder, your account Library folder is often hidden:
Go menu → Go to Folder…, then paste the path above.

[ ] Extract the ZIP
[ ] Copy Matrix-Control.component into Components
[ ] Copy Matrix-Control.vst3 into VST3
[ ] (Optional) Copy Matrix-Control.app into Applications

4.2.2. Clear the quarantine flag (Terminal)
-------------------------------------------
After a browser / GitHub download, macOS may say the app or plugin is
"damaged". You then need to clear the "quarantine flag" once, with
Terminal:

1. Open "Terminal":
   - Shortcut: Command (⌘) + space → Spotlight → type Terminal → Return.
   - Or: Finder → Applications → Utilities → Terminal.
2. In Terminal, type exactly this, then a space (do not press Return
   yet):

     xattr -cr

3. In Finder, drag and drop each copied file onto the Terminal window
   (Matrix-Control.app, Matrix-Control.vst3, Matrix-Control.component).
   macOS writes the path for you. Separate files with a space. Omit
   anything you did not install.
4. When the line looks like this (your paths may differ):

     xattr -cr /Applications/Matrix-Control.app \
               ~/Library/Audio/Plug-Ins/VST3/Matrix-Control.vst3 \
               ~/Library/Audio/Plug-Ins/Components/Matrix-Control.component

   press Return. Usually Terminal shows nothing more if the command
   succeeded — that is normal.
5. Quit Terminal: Terminal menu → Quit Terminal, or ⌘Q.
   You will not need it again for the rest of this guide.

Variant without drag-and-drop: copy the example command (⌘C), paste into
Terminal (⌘V), adapt the paths, then Return.

[ ] The xattr command ran with no error message

4.2.3. First launch and DAW rescan
----------------------------------
[ ] First launch: if macOS says "unidentified developer",
    right-click → Open, or allow in System Settings.
    That is expected for this beta. It is not a bug.
[ ] Launch Standalone: the window opens
    If GETTING STARTED appears: CONFIGURE LATER
[ ] In the DAW: open preferences / settings, Plugins / Audio Units /
    VST section (the name varies by host). Run a rescan or refresh of
    the list (a button such as "Rescan", "Scan", "Refresh" or
    "Reset & Rescan"). Without this step, the plugin may be correctly
    copied on disk but invisible in the list.
[ ] Matrix-Control appears as AU and/or VST3
[ ] Load the plugin on an instrument / MIDI track

What is normal:
- the app and plugins start;
- after xattr, no more "damaged" message in principle;
- an "unidentified developer" warning may still appear:
  right-click → Open.

4.4. Testing on Linux
--------------------------------------------------------------------------------

This section covers Linux, in practice Ubuntu 24 / 26 or a close
distribution.

4.4.1. Copy the files
---------------------
Where to copy the files:

  VST3 plugin →  ~/.vst3/
                 (".vst3" folder in your home directory; ~ = home;
                 the leading dot means it is often hidden in the file
                 manager)
  Standalone  →  binary named Matrix-Control (or similar) from the ZIP
                 — place it wherever you like (Desktop, Applications,
                 etc.)

[ ] Extract the ZIP (right-click → Extract here, or double-click
    depending on your archive manager)
[ ] Create the plugin folder if it does not exist yet, then copy
    Matrix-Control.vst3 into it.

    Method with the file manager (Nautilus on Ubuntu):
    1. Open your home folder (Home).
    2. Show hidden files: Ctrl+H (or View → Show Hidden Files).
    3. If the ".vst3" folder does not exist: right-click → New Folder,
       name it exactly .vst3 (with the dot).
    4. Copy Matrix-Control.vst3 from the extracted ZIP into that .vst3
       folder.

    Command-line variant (if you prefer): open Terminal (Super / Windows
    key, type Terminal, Return), then:

      mkdir -p ~/.vst3
      cp /path/to/Matrix-Control.vst3 ~/.vst3/

    Replace /path/to/… by dragging the .vst3 file from the file manager
    into Terminal after typing "cp" and a space.

4.4.2. Make the Standalone executable
-------------------------------------
[ ] If Linux refuses to launch Standalone ("Permission denied", grayed
    icon, or nothing happens):

    1. Open Terminal.
    2. Type exactly this, then a space (do not press Return yet):

         chmod +x

    3. Drag and drop the Matrix-Control (Standalone) file from the file
       manager into Terminal: the path is written for you.
    4. Press Return. Usually nothing is shown if the command succeeded
       — that is normal.
    5. Quit Terminal (closing the window is enough).

4.4.3. First launch, DAW rescan and audio
-----------------------------------------
[ ] Launch Standalone:
    - double-click the file in the file manager, or
    - from Terminal, to see any error messages:

         /path/to/Matrix-Control

      (drag the file into Terminal after preparing the line, then
      Return)
    If GETTING STARTED appears: CONFIGURE LATER
[ ] In the DAW: open preferences, Plugins / VST3 section, run a rescan /
    refresh. Matrix-Control should appear. Load it on an instrument /
    MIDI track.
[ ] Open SETTINGS → AUDIO and note what is offered (device names, system
    drivers such as ALSA / PulseAudio / PipeWire, possibly JACK). You do
    not need to understand everything: the idea is to know which Linux
    audio path you get, to note it in the session sheet (section 3) if an
    audio problem appears later.

What is normal:
- Standalone and VST3 start;
- no blocking message such as "missing library"
  (shared library / .so not found);
- if such a message still appears, copy it word for word into the notes
  — that is useful for the developer.

7. CHECK MIDI COMMUNICATION
================================================================================

This is the most important software step. Until the synth is recognized
on the MIDI network, a large part of the editor stays locked — that is
intentional, to avoid sending changes "blind".

--------------------------------------------------------------------------------
7.1. Choose or confirm MIDI ports
--------------------------------------------------------------------------------
[ ] Set or check SYNTH FROM and SYNTH TO (FROM SYNTH / TO SYNTH strip,
    or SETTINGS → MIDI & DEVICE)
[ ] When MIDI traffic flows, the LEDs next to the lists blink
[ ] Bottom right, the DEVICE badge shows Matrix-1000, Matrix-6, etc.
    (a Matrix-6R may appear as Matrix-6: note it if that happens)
[ ] If NOT CONNECTED: follow the message at the bottom of the window
    (cables — section 5 —, ports, power-cycle the synth)

--------------------------------------------------------------------------------
7.2. Editing locked then unlocked
--------------------------------------------------------------------------------
[ ] Without correct detection, editing stays locked (normal)
[ ] Once the synth is recognized, PATCH EDIT and useful areas unlock

--------------------------------------------------------------------------------
7.3. Under Windows: MIDI ports already in use
--------------------------------------------------------------------------------
Under Windows, a MIDI port is often reserved for a single application at
a time.

[ ] If the port refuses to open: close the other application / DAW that
    holds it, then try again
[ ] Expected result: DEVICE recognized, editing possible, no cascade of
    errors when ports are correct.

--------------------------------------------------------------------------------
7.4. Matrix-Control version and EPROM type
--------------------------------------------------------------------------------

When the synth is recognized, look in SETTINGS → MIDI & DEVICE (EPROM TYPE
list, and possibly the DEVICE badge bottom right).

On a Matrix-1000: Matrix-Control can query the machine over MIDI
(Device Inquiry) and suggest an EPROM / firmware type from the returned
version. Note what is shown — especially if it differs from what you
thought you had. If the list shows UNKNOWN, note that too.

On a Matrix-6/6R: in practice, that version query is usually unavailable.
The software may still recognize the Matrix-6 family via another MIDI
exchange, without obtaining the EPROM type. Then choose EPROM TYPE
yourself if needed, or leave UNKNOWN if you are unsure — and note what
you see.
(Reminder: a Matrix-6R may display as Matrix-6 — see section 7.1.)

13. MANAGE PATCHES AND MASTERS AS COMPUTER FILES
================================================================================

In the PATCH MANAGER section, the COMPUTER PATCHES module manages patches
as files on disk (one patch per file). Synth memory stays separate
(section 12). Master files are loaded mainly via SETTINGS or by
drag-and-drop (Matrix-1000 only).

As with INTERNAL PATCHES: hover then click the COMPUTER PATCHES title to
give it navigation focus (title in red). The < / > buttons then browse
files in the open folder, not synth memory. Click INTERNAL PATCHES again
to return to internal memory.

Provided test files: preferably use the Test-Data/ folder from the beta
ZIP (see section 4.1) — Patches/syx, Patches/m1kp, Masters/syx,
Masters/m1km. "invalid-*" files are intentionally incorrect
(refusal / valid vs invalid count).

Matrix-Control draws heavily on the "Matrix-1000 Editor", a Max for Live
prototype released on 21 December 2020 — now superseded by this standalone
+ VST3 / AU plugins version, which is much more complete:

https://maxforlive.com/library/device/6806/matrix-1000-editor

That prototype introduced custom formats: .m1kp (patches) and .m1km
(Masters). The .m1km still included Matrix-1000 Groups; Matrix-Control
does not bring those back (of little practical use), while remaining able
to read those files for backwards compatibility.

Supported formats:
  .syx   — Current Matrix-Control format (Patches and Masters)
  .m1kp  — Legacy Matrix-1000 Editor patch (backwards compatibility)
  .m1km  — Legacy Matrix-1000 Editor Master (backwards compatibility)

In this guide, "cleaned name" means: the name is adapted to an 8-character
format and allowed characters (accents / forbidden symbols removed or
replaced, length reduced to 8 if needed).

17.3. Displayed names (Matrix-1000 only)
--------------------------------------------------------------------------------

In SETTINGS, the MATRIX-1000 PATCHES list chooses how to display the name
of a patch loaded from synth memory:

- DISPLAY MUSICAL NAMES (default): prefers a "musical" / factory name
  when available (especially useful on ROM banks);
- DISPLAY HARDWARE NAMES: shows the name as on the machine, or a label
  such as B0-P05 if there is no usable name.

[ ] Matrix-1000: switch DISPLAY MUSICAL NAMES ↔ DISPLAY HARDWARE NAMES;
    load a patch in a factory bank then in a RAM bank — PATCH NAME (or
    the related label) changes coherently with the option; note what
    you see
[ ] Matrix-6/6R: mark [-] (this list does not apply)

--------------------------------------------------------------------------------
17.4. HARDWARE LATENCY (plugin only)
--------------------------------------------------------------------------------

HARDWARE LATENCY (MIDI & DEVICE tab) tells the DAW a delay in
milliseconds to better align synth audio (which goes through your audio
interface) with the rest of the project. It does not change Matrix sound
itself: it informs the host so it can handle latency compensation. Adjust
only if you notice MIDI/audio offset in the DAW.

[ ] Plugin only: HARDWARE LATENCY is visible and adjustable; a small
    change of the value does not crash the plugin or the DAW
[ ] Standalone: HARDWARE LATENCY does not appear — that is normal
    (mark [-] if you only test Standalone)
