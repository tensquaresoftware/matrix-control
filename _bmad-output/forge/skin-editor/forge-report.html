Forge Report — Skin Editor

Matrix-Control · post Skin SSOT · 2026-10-23 · session skin-editor

Issue : idée durcie — télécommande JUCE (même repo, cible Dev) qui pousse un calque auteur vers Standalone Dev ; Skin SSOT C++ reste la vérité produit ; alpha non otage.

Décisions verrouillées

  • Job = inventer (skins Dev nommés) ; premier usage depuis Black/Cream.
  • Seuil = Duplicate + live + Unbound ; JSON = cible avec filet sans I/O.
  • App JUCE séparée, pousse-modèle only ; vérité = Standalone Dev ; pas d’aperçu produit dans l’éditeur.
  • C++ = SSOT produit ; calque Dev + JSON calque ; BC lecture seule → Duplicate.
  • Unbound = texte dans l’éditeur (noms structurés), pas d’overlay sur le paint.
  • Même repo / cible CMake Dev ; éditeur d’abord comme priorité, alpha OK sans lui.

Rejeté — et pourquoi

  • Panneau in-app dans le layout Release — pollution Dev sur GUI chaude.
  • Coquille web / Skin Studio — risque second studio + preview qui revient.
  • JSON = SSOT Release — rouvre la porte modèle.
  • Édition en place de Black/Cream compilés — confusion vérité produit.
  • Plugin-in-DAW + sync riche — complexité sans gain auteur solo V1.
  • Repo séparé V1 — dérive du contrat Skin SSOT sans lib partagée.
  • Alpha bloquée par l’éditeur — contredit filet Black/Cream viables.

Faiblesses qui restent

  • Pont IPC + cycle de vie deux process : toujours une dette receiver Dev côté Matrix-Control.
  • Périmètre (2ᵉ app + calque + Unbound + JSON cible) plus large qu’une migration de tables — « quelques jours » reste une hypothèse optimiste.
  • Peaufinage fier = Duplicate → itérer → réintégration C++ manuelle : friction assumée.
